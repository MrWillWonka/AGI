# The Path to AGI

Browser-based incremental (idle/clicker) game. Vanilla JS, no build step, no runtime dependencies.

## Commands

```bash
python3 server.py            # http://localhost:8000, no-cache; add --no-browser in headless envs, or pass a port
node --test                  # engine unit tests (Node 18+, no install needed)
```

Open the debug panel (`debug-panel.js`, which talks only to `AGI.debug`) by **tapping the title three times in a row** (the owner's call: it's hidden, no icon in the top bar; each tap within half a second of the last, `pointerup` so it works on a phone and inside the artifact), with `/?debug` or `#debug` (only a `#hash` reaches an artifact), or with <kbd>`</kbd>; it's remembered per device, and its × (or three more taps) closes it. **Its sections fold** (the owner's call: ordered by use, which are open remembered per device in `localStorage['agiDebugOpen']`, Packet Snare and Jump ahead open by default): at the top, always there, **Start over (back to the inbox)** (no confirmation: a fresh save and a reload, `startFresh`, so the game opens on the inbox's opening as a new player sees it) and **Save now**; then Packet Snare, Jump ahead (the next skill, a phase, everything), Training (with Power-ups), Resources (add, attributes, per second, rate multipliers), Time (game speed, simulate), Lab, Server room, Versions, Music and State. What each does:
- **Resources / Attributes:** add any amount (XP included; added CP counts as earned this run, so it moves the hardware reveals and shipping).
- **Per second:** a flat amount of any resource (Insight included) added every second of game time, on top of production (`AGI.debug.income`; follows game speed and Simulate; debug CP counts as earned). 0 turns it off.
- **Rate multipliers:** CP, DP, RP and XP/s (cleared stretches).
- **Time:** simulate N seconds, or set a **game speed** (1×/2×/5×/20×) for both the economy and the training physics.
- **Progress:** learn the next skill, reach a phase, or unlock everything.
- **Versions:** add a version without resetting (+10 Insight; opens R&D and the legacy nodes), ship the next version now, or max every legacy node; open the challenges, beat the running one, or make Transcend ready (the Singularity).
- **Lab:** fill, finish or clear investor offers; meet every automation's "by hand" gate; +10 of every hardware tier (watch the cabinets merge); +1 of every visible lab upgrade; a test line in the lab log.
- **Packet Snare:** **Open Packet Snare** (on any save: the server room opened, skills learned up to Edge Detection, straight into the bay; the panel closes so the field is clear on a phone); **Boss now / clear sector** (`AGI.debug.snareBoss()`: the run's boss boots now, or a goal sector's goal is met in the run, else the sector is cleared); **Max snare tree** (`AGI.debug.snareMax()`: every node at its last level, Overclock at 5); **Go to sector** n (`AGI.debug.snareSector(k)`, 0-based); **Reset Packet Snare** (`AGI.debug.resetSnare()`: Signal, the tree, sectors, records and the saved layout cleared, its first-meeting cards shown again, back to sector 1; the rest of the game stays); `AGI.debug.snareRun()` reads the run in play. **Resources** has +Signal.
- **Server room:** +50 automated laps on every cleared leg; set the frontier record to 90%; reset room visits and the cabinets' order.
- **Music:** what's playing (area, song, section, bar), **Next song** (the area's other one) and **Next section**, on the next downbeat.
- **Power-ups:** Breakthrough and Paradigm Shift (on your next sprint), Max Effort, Crunch, Bullet Time, Flow and Lucid Dream (on the ball in flight, else your next sprint), System prompt (your next release), Viral (the next run's end).
- **Training:** finish the run; **Fling the ball** (throws it into the air: flights, bounces and the late-leg camera); **Test summit** and **Test near miss**, which put the ball on the skill hill's climb just above or below the exact speed needed (found by simulating a copy of the run); max the skill tree; toggle the Auto-Trainer; reset the tree view; **Reset Training Cluster** (`AGI.debug.resetTraining()`: back to the warm-up, no skills (their attributes taken back), no XP, an empty skill tree, records, laps and runs cleared; legacy nodes, the lab and Packet Snare stay).
- A live state view.

**Review builds open straight into Packet Snare** (the owner's call): `window.AGI_SNARE_DIRECT = true` before the scripts, or `#snare` in the URL, skips the opening (its mails marked read, the offer accepted) and opens the bay as Open Packet Snare does (`straightToSnare`), on every load. `node tools/review-index.js <out.html>` writes the review artifact's index.html with the flag set; the game's own index.html stays as it is.

## Architecture rules

- **Content is data.** Actions, tabs, upgrades, milestones, achievements and phases are arrays in `engine.js`. Add an upgrade by adding an `UPGRADES` entry (`scale` = repeatable, `max: 1` = one-time, `grants` = attributes per level, `requires`/`unlock`/`hint` = gating) and, if it affects production, a term in `derive()`. The UI picks it up automatically.
- **Derive, don't store.** Production rates come from `derive(state)` using upgrade levels; phase comes from `phaseIndex(state)` using attributes. Only store what the player earned (resources, attributes, levels, unlocks, achievements, stats).
- **Unlocks are sticky.** `evaluate()` records milestone/upgrade unlocks in `state.unlocked` and achievements in `state.achievements`; it returns what changed so `game.js` can log/toast it once.
- **Saves.** `localStorage['agiGame']`, versioned (`SAVE_VERSION`). `migrate()` sanitizes any input (wrong types, negatives, unknown ids) and converts the original v1 format. If you change the state shape, bump `SAVE_VERSION`, extend `migrate()`, and add a test. **Save safety:** one tab plays at a time (`claimTab`: a tab that opens the game claims it on a `BroadcastChannel`, the newest wins; the others save once, stop ticking and saving, and offer **Use this tab**, which reloads; two tabs used to write over each other). The handover message carries the save itself (`json`): another tab's storage can lag behind the channel, and the new tab read the save from before. A good save is copied to `agiGame.bak` on load, every 10 minutes and before an import; an unreadable save is kept in `agiGame.corrupt` and the backup restored (else a new game), with a dialog holding the raw text. Import shows both games' summaries (`saveSummary`) and warns about a newer save version; **Restore backup** (Settings) swaps the game and the backup.
- **Automation converts, it never creates.** The Auto-Collector (the "Data crawler") spends CP for DP and the Research Assistant spends CP and DP for RP, at the manual action prices. Each is a **scheduled task** (`TASKS`, `state.tasks`, save v5) with an on/off switch and its own share of each second's production, "dedicated compute" (`taskShares`, defaults 25% and 20%; research takes the same share of DP). **A slider means what it says** (the owner's call: at 100% the crawler took 2 CP/s, its level's speed limit, while the Procurement Bot took everything): the crawler and the assistant spend all of their share at the hand price, so their share sets their speed, and their levels make each collection or research run yield more (+25% a level past the first, `autoEff`; their cards show DP per collection and RP per research, now → after). **Each slider goes to 100% on its own** (the owner's call: players push one up for a short-term gain or to learn where they like it; capping each at what the others left felt like a limit); past 100% together they spend more than comes in and the rest comes out of the stockpile (the owner's call: players see and feel the bank fall), each spend stopping at an empty bank; the panel's total says "drawing on the stockpile". The Auto-Trainer is a task too (switch only, `autoTrainerLevel`), but its switch lives in the server room, where you watch it (see Auto-Trainer); its Scheduled tasks row only reports. **Its first level is earned in the first version** like the lab's machines (`AUTOMATION.autoTrainer`: `AUTO_TRAINER_RUNS` 25 runs by hand and `AUTO_TRAINER_SKILL` 4 skills learned, the warm-up's included, i.e. Edge Detection (`SKILL_INDEX['Edge Detection'] + 1`); the milestone `auto:trainer` grants `prestige.levels.autoTrainer` 1 for good, switched off, with a prompt to turn it on outside the Training Cluster; the run view's stats show the gate, `#autoGate`, from Pattern Matching until it's met): the sprint was the one verb never handed off before a version shipped (round-one design review). Levels 2 and 3 stay legacy (2 and 4 Insight). Only hardware creates CP. The top-bar rates are net (`cpNet`, `dpNet`).
- **Procurement** (design review round 2): the lab's buying is delegated too. The **Procurement Bot** (hardware bench, 400 CP, one-time; earned with 20 hardware bought by hand and Edge Detection, `AUTOMATION.procurement`, which counts hardware owned) is a scheduled task with its own share of compute (default 20%, claimed only once bought: `owned` on the task, `taskClaims`). Its share goes into a fund (`tasks.procurement.fund`, save v15, emptied by a new version) while there's hardware below capacity, and whenever the fund covers it, it buys the visible tier with the most CP/s per CP (`procurementPick`); its row shows the next buy and the fund, and its buys go to the lab log. Why: sprints charge up to whatever you hold, so in the sim the training half spent every CP and hardware stopped growing from about 35 minutes (passive stuck at 0.9× a held button; act two's walls took 25–75 min). With it: passive 2.6–4.7× a held button at 45 min and 6–16× at 60. Once bought it stays across versions and Transcend (`keptAutomation`, round B's deep audit): the inherited Auto-Trainer sprints with every CP from a new version's first second, so the bot's 400 CP was never saved again and version 2's lab sat at 15 CP/s for an hour (the sim: v2 reached Superintelligence in 22 of 33 ship points, 33 of 33 with it kept). It's cheap and earned early on purpose: a player who trains a lot spends every CP on sprints and can starve the lab (the sim's seed 42 sat on skill 9 for 100 minutes with 25 hardware when it cost 2,500 CP and needed 40).
- **Automation is earned** (`AUTOMATION`, `automationGate()` in `engine.js`): each machine that does a job for you needs proof you've done it by hand (a stat count) and, for the bigger ones, a training skill. Graphics Card (the first generator, id `cpu`): 40 computes by hand and the click tool grown to the Server Rack (level 5, `CPU_AFTER_CLICK_LEVEL`; the click tool shows first, at 15 computes), so you build up your desk before automating. Collect Data itself only appears at 5 CP/s of passive compute (milestone `action:collect`), and Research after the first skill plus 50 paid training sprints (`action:research`, `RESEARCH_SPRINTS`, counted in `stats.skilledSprints` by `payPush` once a skill is learned; older saves past the first skill estimate 2 per run; costing 200 CP and 40 DP). After the first shipped version Research stays open (and the investors with it). Compiler Optimizations at 10 Server Clusters, so compute options arrive one at a time. Auto Data Collector: the first skill (Pattern Matching) plus 40 collections by hand (`stats.collects`; the server room already needed 40), so data automation arrives with the first skill. Research Assistant: Language Modeling plus 25 research runs by hand (`stats.researchManual`; 50 was about 10K CP of mashing). The Workbench's compute line shows the desk's progress ("desk 3/5") until it's built, and gates name the skill they wait for. Hand counts carry across versions for the gates (`stats.collectsEver`, `researchManualEver`): a gate met once stays met, so a new version doesn't repeat 40 collections and 50 research runs by hand (the version's own counts still reset, for the reveals and investor tasks). Each automation level costs much more than the last (×1.5 / ×1.55). Later automation can also be gated behind stations, rooms or prestige upgrades.
- **Hardware is a spaced-out generator ladder**, like most incremental games: each tier (`cps` on its `UPGRADES` entry, summed over `HARDWARE` in `derive()`) costs 20× the last and gives about 6.7× the CP/s, so it pays back 3× slower (30 s, 90 s, 4.5 min, 13 min, 40 min, 2 h for one unit). When a tier appears, the one below stays the better buy for about eight more units before the new one takes over; the old 12× ladder made each tier stale as soon as the next showed up. All cost ×1.15 per unit, and a tier's output doubles at 25, 50 and 100 owned (`HARDWARE_DOUBLINGS`), which makes older tiers worth topping up again. A tier shows up only once you own ten of the tier below and have earned its full price this run (`tierReady`; the top two also need their phase). **Cards carry the numbers, not the descriptions:** every lab card has a live line (`yieldText`): hardware shows CP/s each (every multiplier in; `derive().hardwareRates`), never the next doubling; other cards show the one number they change, as "now → after the next level" (the upgrade's `shows`: `click`, `collect`, `research`, `hardwareMult`, `autoCollect`, `autoResearch`; attribute upgrades show the attribute totals). **The click tool** is one repeatable upgrade (`keyboard`) that grows through `CLICK_TOOLS` as you level it, your desk first, one item per level at its own price (`costs` on the upgrade: Desktop Tower 15, Mechanical Keyboard 25, Gaming Mouse 40, Monitor 60 CP, each +0.25 per click, so a click reaches 2 CP; then the Server Rack, 75 CP, +1: the owner lowered them from 25, 45, 45, 75 and 100), then ×1.32 per level from 100 CP (`cost`, so the later stages kept their prices) through Macro Pad → Summer Intern → Team of Interns → Crowdsourcing Platform → Click Farm → Robotic Clicker Arms, each stage adding more CP per click per level (3, 6, 15, 40, 110: halved in the design review, so hands don't keep pace with hardware) (`clickToolPower`). The card's name and flavour follow the stage (`upgradeName`/`upgradeFlavor`), and its line never names the next one (growing into it is a surprise; it goes to the log). Software multipliers: Compiler Optimizations and Kernel Fusion (+50% hardware each). NLP and Computer Vision do what their names say (the owner's call: both used to speed up the crawler): NLP +2 data per collection, by hand and by the crawler; Computer Vision makes sprints use 30% less compute (`pushCost`). Tested: the ladder's ratios, the doublings, the reveal rule, and that Server Cluster no longer touches clicks.
- **Achievements** (53: Packet Snare's six, and the early list, a mid-game set (runs, skills, prompts, super prompts, breakthroughs, replays, the tree; playtest 2 went 34 minutes without one; `stats.breakthroughs`/`superPrompts` count for them), plus a long-term one for versions, challenges, Transcend, flights, tokens, investors, replays and totals, and the hidden **The IT Department's Favorite** for every opening spam variant) are recognition only, with no production bonus (they used to add +2% each, which made a click 1.02). - **Hand actions pay whole numbers:** a click, a collection or a research run by hand adds only flat amounts (the click tool, Data Processor, the algorithms, skills' `click`/`collect`/`research`). Percentage bonuses (skills' `dp`/`rp`, Insight) go to what runs by itself: hardware, the Data crawler and Research Assistant (`autoDpPerCollect`, `autoRpPerResearch`) and training XP. A click never reads 2.3 DP or 3.60 CP (tested).
- **Supply chain (the lab feeds training):** the lab produces compute and data, training sprints spend them (the late cost ramp makes income limit charges: about half of the sim's sprints fall short of full), learned skills boost the lab and unlock its automation, and every lab currency also buys training: data the **Training Data Pipeline** (software, endless, +8% sprint strength per level, from Pattern Matching, the first real skill: not the warm-up, the owner's call, so the first trip to training doesn't just send you back to the lab), research the algorithms' training effects (Machine Learning +10% XP, Deep Learning +15% strength, Reinforcement Learning +1 sprint, Transfer Learning +25% XP: lab upgrades may carry a `boost`, summed with the tree's in `treeBoosts`) and **Published Papers** (endless, research only, +10% training XP per level), and investors pay in training XP. The Training Data Pipeline, research and one-time upgrades are never capped. Sprints cost more to match (`pushCost` 24 CP, 2.5 DP, ×1.5 per early stretch; it was 14, 1.5, ×1.4). - **Tree pricing:** a node's first level always costs more than its parent's last level (tested), so finishing a node is never worse value than skipping ahead (Lucky Break 2 used to equal Serendipity 1). **Power-ups are found across the tree, and their power comes after them:** breakthrough nodes sit in three branches and never grow from one another (Lucky Break off Fast Charging, Serendipity off Data Augmentation, Black Swan off Mixed Precision, Fusion Reactor up the Power line; tested), and a node that powers up a power-up waits for the node that brings it, wherever it is (`after` on the node, checked in `upgradeUnlockMet`: Serendipity, Black Swan and Fusion Reactor show only once Lucky Break is owned; Quantum Accelerator grows from Max Effort; tested). **No repeats down a path or across siblings:** a node never boosts the same stat as the node it grows from, and nodes growing from the same node never share a stat either (both tested), so each step and each choice feels new. **The shape stays mirror-symmetric:** the inner ring branches both ways off Power (Batch Normalization right, Smoother Loss Landscape left) and Recursion (Warm Restarts left, Data Augmentation right) while Momentum and Precision run straight, because one side node per arm, each bent the same way round, read as a swastika. Worth (scratchpad `hopval.js`: a bot sprinting at stalls, three clean hops at the first lips): +25–60% of the distance a run covers, against +2–5% for one more sprint; tested that it floats, lands clean and carries runs further. **Timing it** (the same log: on a phone the perfect window was 4–12 px and 25–135 ms, under touch latency): **holding Hop sets a breakpoint** (`startAim`/`releaseAim`, `path.hopAim`; pointer captured on the button, E/W/↑ keydown and keyup): time slows to `HOP_AIM_SCALE` 0.35 for up to `HOP_AIM_MAX` 2.5 s a press, the camera leans in on the ball and the rolling hills ahead (`aimView`, camera language's fifth move: as close as their height allows, never under `AIM_VIEW_MIN` 2.2 m, wide enough to show the next lip; eased by `path.aimT`), a ring closes on the ball over the last `HOP_AIM_RING` 0.5 s before the next lip and locks on, filled, inside it (`drawHopAim`, an approach circle: it reads the timing whatever the zoom), and the frame gets a violet edge and a ❚❚ BREAKPOINT tag (`drawBreakpoint`); **letting go hops** (a quick tap still hops at once).
