# The Path to AGI

Browser-based incremental (idle/clicker) game. Vanilla JS, no build step, no runtime dependencies.

## Commands

```bash
python3 server.py            # http://localhost:8000, no-cache; add --no-browser in headless envs, or pass a port
node --test                  # engine unit tests (Node 18+, no install needed)
```

Open `/?debug` (or press <kbd>`</kbd>) for the debug panel (`debug-panel.js`, which talks only to `AGI.debug`):
- **Resources / Attributes:** add any amount (XP included).
- **Rate multipliers:** CP, DP, RP and XP/s (cleared stretches).
- **Time:** simulate N seconds, or set a **game speed** (1×/2×/5×/20×) for both the economy and the training physics.
- **Progress:** learn the next skill, reach a phase, unlock everything, or add a Transcend (opens R&D).
- **Luck:** trigger a breakthrough, crunch, flow state or viral run (the next run's end) to see the effects.
- **Training:** finish the run; **Test summit** and **Test near miss**, which put the ball on the skill hill's climb just above or below the exact speed needed (found by simulating a copy of the run); max the skill tree; toggle the Auto-Trainer; reset the tree view.
- **Save:** save now, or start over (wipes the save and all screen state: open bay, result card, room visits, tree view).
- A live state view.

## Layout

| File | Role |
|---|---|
| `engine.js` | **All game rules and data**, no DOM. UMD: `window.AGIEngine` in the browser, `require()` in Node |
| `training-path.js` | Training Path physics: trail geometry and a fixed-step ball sim (`window.TrainingPath` / `require()`). Pure: no DOM, no clock, no randomness |
| `game.js` | `window.AGI`: builds the UI from engine data, input (hold-to-repeat), 100 ms loop, render, save/load/export, and the Training Path canvas view |
| `debug-panel.js` | Dev tools; talks only to `AGI.debug` |
| `index.html` | Static shell; dynamic parts are generated by `game.js`, values bound via `data-bind="key"` (see `bindValue`) |
| `styles.css` | All styles. "Night survey" single dark theme: tokens on `:root`, fonts Chakra Petch (display), Atkinson Hyperlegible (body), JetBrains Mono (numbers). Screen-size tiers at the end |
| `tests/*.test.js` | `node:test` suites for the engine and the Training Path |

## Architecture rules

- **Content is data.** Actions, tabs, upgrades, milestones, achievements and phases are arrays in `engine.js`. Add an upgrade by adding an `UPGRADES` entry (`scale` = repeatable, `max: 1` = one-time, `grants` = attributes per level, `requires`/`unlock`/`hint` = gating) and, if it affects production, a term in `derive()`. The UI picks it up automatically.
- **Derive, don't store.** Production rates come from `derive(state)` using upgrade levels; phase comes from `phaseIndex(state)` using attributes. Only store what the player earned (resources, attributes, levels, unlocks, achievements, stats).
- **Unlocks are sticky.** `evaluate()` records milestone/upgrade unlocks in `state.unlocked` and achievements in `state.achievements`; it returns what changed so `game.js` can log/toast it once.
- **Saves.** `localStorage['agiGame']`, versioned (`SAVE_VERSION`). `migrate()` sanitizes any input (wrong types, negatives, unknown ids) and converts the original v1 format. If you change the state shape, bump `SAVE_VERSION`, extend `migrate()`, and add a test.
- **Automation converts, it never creates.** The Auto-Collector spends CP for DP and the Research Assistant spends CP and DP for RP, at the manual action prices. It may only use the **automation budget** (`settings.autoBudget`, 0–100% of each second's CP and DP production, default 50%, slider in the lab) and never touches the stockpile, so compute never falls. Over budget, both slow down evenly (`derive().autoThrottled`). Only hardware creates CP. The top-bar rates are net (`cpNet`, `dpNet`).
- **Automation is earned** (`AUTOMATION`, `automationGate()` in `engine.js`): each machine that does a job for you needs proof you've done it by hand (a stat count) and, for the bigger ones, a training skill. Basic CPU: 25 computes by hand. Auto Data Collector: the first skill (Pattern Matching) plus 100 collections by hand (`stats.collects`), so data automation arrives early. Research Assistant: Language Modeling plus 50 research runs by hand (`stats.researchManual`). Automation starts slow (0.2 and 0.1 jobs/s per level) and each level costs much more (×1.5 / ×1.55). Later automation can also be gated behind stations, rooms or prestige upgrades.
- **Hardware is a spaced-out generator ladder**, like most incremental games: each tier (`cps` on its `UPGRADES` entry, summed over `HARDWARE` in `derive()`) costs 20× the last and gives about 6.7× the CP/s, so it pays back 3× slower (30 s, 90 s, 4.5 min, 13 min, 40 min, 2 h for one unit). When a tier appears, the one below stays the better buy for about eight more units before the new one takes over; the old 12× ladder made each tier stale as soon as the next showed up. All cost ×1.15 per unit, and a tier's output doubles at 25, 50 and 100 owned (`HARDWARE_DOUBLINGS`), which makes older tiers worth topping up again. A tier shows up only once you own five of the tier below and have earned half its price this run (`tierReady`; the top two also need their phase). **Cards carry the numbers, not the descriptions:** every lab card has a live line (`yieldText`): hardware shows CP/s each (every multiplier in), the total and the next doubling (`derive().hardwareRates`); other cards show the one number they change, as "now → after the next level" (the upgrade's `shows`: `click`, `collect`, `research`, `hardwareMult`, `autoCollect`, `autoResearch`; attribute upgrades show the attribute totals). **The click tool** is one repeatable upgrade (`keyboard`) that grows through `CLICK_TOOLS` as you level it: Mechanical Keyboard → Gaming Mouse (level 6) → Macro Pad → Summer Intern → Team of Interns → Crowdsourcing Platform → Click Farm → Robotic Clicker Arms, each stage adding more CP per click per level (`clickToolPower`). The card's name and flavour follow the stage (`upgradeName`/`upgradeFlavor`), its line names the next one, and growing into a new tool toasts. Shell Scripts: clicks also earn 2% of CP/s per level. Software multipliers: Compiler Optimizations and Kernel Fusion (+50% hardware each); NLP ×1.5 and Computer Vision ×2 data per collection. Tested: the ladder's ratios, the doublings, the reveal rule, and that Server Cluster no longer touches clicks.
- **Supply chain:** the lab produces compute and data, training sprints spend them, and learned skills boost the lab and unlock its automation. Both sides show it: the lab's compute output shows the bonus cleared stretches give, the Workbench says which skill opens each automation, and the Training Cluster bar shows the lab's supply.
- **Reveals:** top-bar chips appear only once they matter (`REVEALS` in `engine.js`: `seen:dp`, `seen:int`, `seen:cre`, `seen:awa`; the phase bar shows with Intelligence). Each is introduced once with a toast and a log line. XP lives in the Training Cluster bar, not the top bar. The Software station opens with `seen:dp`.
- **Investor projects** (`engine.js`, save v3): once the Training Cluster runs, offers arrive every 2.5–5 min of game time (`PROJECTS`, at most 3), each an investor, an optional task with a deadline (`PROJECT_TASKS`: computes or collects by hand, finish runs, clean sprints, earn CP, research), and a reward (`PROJECT_REWARDS`: a temporary +% boost to compute, data, XP or sprints, or a one-off XP or CP payout). Progress counts from when the offer arrived. Claim when done (`claimProject`), or ignore and it expires. Boosts multiply in `derive()` via `projectBoosts`. Seeded by `projects.seq`, so tests are deterministic. The lab shows them in the supply strip, with active boosts and timers; rows are rebuilt only when the offers change.
- **Offline progress** is applied on load and for long gaps between ticks, capped at `MAX_OFFLINE_SECONDS`, and respects `settings.offline`.
- Keep `engine.js` free of DOM/`window` so it stays testable.
- **Training Path** (how the AI learns):
  - The trail is a series of stretches. Stretch k runs from a checkpoint to **skill hill k** (fixed, grows each stretch). Cresting it learns `skillAt(k)`: attributes plus a permanent bonus summed in `derive()` via `skillBonuses()`.
  - Each **roll** starts at the checkpoint over **random rolling hills** (`rollingHills(k, seed)`, new seed per roll from `rollSeed`). The roll ends when the ball rests with no pushes left, or crests the skill hill. Distance earns **XP** (`finishRoll`), and the furthest roll is the stretch record (`path.best`).
  - **Flat start:** nothing is behind the start line (no wall, no previous hill), and a ball that rolls back past it (`ROLL_BACK`) ends the run (`end` with `rolledBack: true`, progress 0, paying for half the furthest distance reached; the card says "Rolled back to the start"). The drawing is flat there too, except in the post-skill overview.
  - Once the ball lacks the energy to clear either neighbouring hill it is "trapped" and gets heavy damping, so it settles in about a second instead of sloshing. Full momentum otherwise.
  - Pushes add a fixed amount of *energy* (pushing against a backward roll is wasted), and drag is partly quadratic. So saving pushes to rescue a stalling ball beats firing them early. Tests guard this; keep it true when tuning.
  - **Pushing is hold-to-charge.** A meter sweeps up and down while the button (or Space/Enter, or the canvas) is held, and release fires at that fraction of `pushPower`.
    - Every push costs CP and DP by `pushCost(s, charge)` (∝ charge², scaled per stretch), so passive income gates how hard you can push. The meter only reaches `affordableCharge()`.
    - Each push has a **bonus zone** (`bonusZone(seed, index, width, perfect)`, centred between 50% and 85%), and `zoneHit()` classifies a release as `'clean'`, `'perfect'` or none.
    - A clean push banks a small flat amount of XP at once (`grantPushBonus`) and adds `cleanRollBonus` to the roll's distance XP; a perfect push counts as `perfectMult` clean pushes (`cleanUnits`). This is the trade-off: steady XP from the zone, or full charge for distance.
    - **The sweet spot never widens** (`PATH.zoneWidth` 10%, perfect spot 2.5%, +25% per Fine or Laser Calibration level, capped at 40% of the zone): wide zones made it trivial and the upgrades felt wasted. Upgrades make hitting it *pay* instead: a sprint's strength is `sprintStrength(s, fraction, kind, breakthrough)`, ×`cleanPower` in the zone (Hyperparameter Search +20%) and ×`perfectPower` on the perfect spot (+30% more, Fine Calibration +20% per level). Benchmark and Leaderboard Prizes (flat XP), Curated and Hand-Labelled Data (run bonus). The meter shows the boosted strength while you're in the zone. Tested.
    - **Fast Charging** (`charge` stat → `sweepScale` < 1) makes the meter faster; the base sweep is `CHARGE_SWEEP_MS` 1250. The Auto-Trainer pushes at its full budget and never scores clean pushes.
    - **Luck** (Capability branch): earned and rare. The branch opens only after the second skill (Lucky Seeds' `unlock`), chances start at 2–3% per level, and the strongest kinds sit at the far end behind Keynote Demo. Rolled deterministically from the roll seed and push index (`luck()` and `*Hit` in `engine.js`), so tests and the sim are repeatable; chances cap at 50%. Each has its own special look (`game.js` "Luck effects", `drawLuckUnder`/`drawLuckOver`, a big popping banner via `luckBanner`, styles.css "Luck"):
      - *Breakthrough* (Lucky Seeds, Serendipity: `critChance`, `critMult` from ×1.5): the sprint hits that much harder. On screen the ball **winds up** first (`WINDUP_SECONDS`, the run holds still): it glows, shakes harder and harder and draws sparks in, then takes off with a shockwave, a burst, a golden streak behind it and a jolt of the trail.
      - *Viral run* (Viral Paper, Keynote Demo: `windfallChance`, `windfallMult` from ×2): the run's distance XP is multiplied. Reactions (♥ ↑ # ★) pour off the ball, and the result card gets an animated rainbow edge and a "VIRAL ×N" stamp.
      - *Crunch Time* (`crunchChance`, `crunchSeconds` 3 s +1 per level): a paid sprint can set off a crunch: for a few seconds every sprint is free (no push used, no CP or DP, `roll.push(strength, true)` with a 0.35 s wait), and `holdOpen` keeps a resting ball's run going. A fiery aura with rising flames and a countdown ring on the ball, and a burning sprint button.
      - *Flow State* (`flowChance`): your next sprint is perfect wherever you release (manual sprints only). A cyan rotating halo on the ball and a shimmering gold meter.
      - The debug panel's **Luck** section triggers each one on demand.
    - XP follows the ball: the live pill shows `rollXp` at the ball's *current* position, and the payout uses where it stops (rolling back loses XP). The result card sits top-right, clear of the checkpoint; launching fades it.
  - Slope friction (`SLOPE_DRAG`): steeper slopes sap more speed than gentle ones.
  - **Friction stays a skill.** Upgrades only take the edge off: each drag step is −5% (`friction`), and "less steep hills" (`slope` stat → `hillScale`, ×0.94 per step) really lowers the *rolling* hills, never the skill hills (`rollingHills(k, seed, hillScale)`). Skills add little glide. Don't make hills trivial.
  - **Difficulty grows every stretch:** `skillHeight` ×1.5 per stretch, and `stretchLength` = 10·1.4^k + 3k (10, 17, 26, 36, 50, 69, 93, 124, 166 by stretch 8; `training-path.js`): gentle early, so the second skill isn't a wall, then much longer each stretch, so the distance itself becomes the challenge and strength (and later launches and bounces) matters more than the hill count. The number of rolling hills grows with the length. Chosen by simulating several curves for the steadiest growth in the gaps between skills; doubling every stretch from the second made the second skill a 35-minute wall. Later stretches pay more (they're longer, and `metreScale`). Skills answer with growing bonuses (push %, extra pushes, a little glide; `SKILLS` and frontier skills), and the tree's outer ring (Quantum Accelerator, Exascale Cluster, Superconductors, Neural Compression, IPO) is priced for the late hills.
  - **Cleared stretches train themselves:** each learned stretch earns `stretchXpAt(k) × PATH.clearedRate` (1/600) XP per second (`derive().xpPerSec`, applied in `tick()`, shown on the XP chip). It's slow on purpose.
  - **Replays (legs):** every cleared stretch is a leg you can run again. A run can start on any cleared leg (`createRoll(k, seed, { last })` builds the terrain from leg k through the frontier, each leg with its own rolling hills from `legSeed`), and keeps rolling through every later leg. Crossing a cleared leg's skill hill emits `clear` and pays flat XP at once (`clearLeg()`: `PATH.replayXp` (25%) of that leg's full XP, more for later legs). The roll ends like any other: where it stops (`end` events carry the `leg` and the `progress` along it), paying distance XP at the replay share on a cleared leg and in full on the frontier, where it can still set the record or learn the skill. Pushes cost what they cost on the leg the ball is on (`pushCost(s, charge, leg)`), so later upgrades make early legs quick and cheap. Pick the leg by clicking a cleared lane on the rack (it shows "▶ Replay" on hover; the rest of the bay opens the frontier) or with **Start at** on the dev screen; a tag on the trail shows a replay, and its × goes back to the frontier (`path.startLeg`, screen state only).
  - **Cleared stretches feed the lab:** each adds `PATH.clearedCp` (+3%) compute, and every automated lap of it (`state.path.auto[k]`, one per `clearedPeriod(k)` = 40 + 5k s, counted in `tick()`, save v4) adds `PATH.lapCp` (+0.2%) more, up to `lapCpMax` (+50%) per stretch (`clearedCpBonus()`, in `derive()`). The rack's cleared lanes draw those same laps, and the lab's compute output shows the bonus.
  - **Drama** (`game.js`):
    - A *nail-biter* (`nailBiter()`) is the ball climbing near the top of a big hill with about as much energy as it needs. It brings slow motion (`path.timeScale`), a camera push-in raised to the ball (`cameraTarget` with `cam.bottom`), a vignette and "Will it learn <skill>?" (or "Come on…" on a rolling hill).
    - Rolls use `rollOut`: cresting the skill hill fires `celebrateSummit()` (a SUMMIT! banner, confetti across the whole trail, slow motion, the push-in held). The ball then rolls down the far side, and the skill is announced when that roll ends (an `end` event with `crested: true`).
    - Slow motion only applies on screen; background runs keep real time.
  - **XP is paid by distance:** `rollXp` = `xpPerMetre` (0.45) × `metreScale`^leg (1.05) × metres along the leg (`end` events carry `metres`, from `legLength`) × (1 + progress), ×2 for cresting, times the clean-push and XP bonuses. `stretchXpAt(k)` is exactly what reaching leg k's peak pays (`legMetres` mirrors the physics; a test keeps them in step), and it sizes everything "per stretch": clean-sprint XP, replay flats, passive XP and investor payouts. (When it was a separate 20·1.5^k curve, clean sprints out-earned distance.) Longer legs pay for their length, short runs still earn, and getting further pays more than linearly. (A per-hill floor used to dominate on long legs, so runs paid by hill count; don't bring it back.)
  - **Runs and the dev screen.** One run is one roll over a long stretch (about 10–12 rolling hills before the first skill hill, many more on later legs). When it ends, the result card waits (`path.done`) with **Run again** (or hold the push button) and **Upgrades →**, which switches the bay from `#runView` to `#devView`: where you stand, XP to spend, the skill tree and Start run. Nothing advances on a timer, except with the Auto-Trainer, which starts the next roll by itself. `path.view` is `'run'` or `'dev'`, and physics only runs in `'run'`. The first visit goes straight to the run view; later visits open the dev screen.
  - **Skill tree.** Training upgrades (`tab: 'training'`) are nodes with a `tree: {x, y}` grid position around the Training Core at (0, 0), an `icon` (glyphs in `ICONS` in `game.js`), `requires` (the adjacent node they grow from; none means attached to the core) and a `boost` per level, summed by stat in `treeBoosts()` and applied in `derive()`. Branches: Power (up), Precision (right), Recursion (down), Capability (left), listed in `TREE_BRANCHES`. A node becomes buyable when its parent is owned (`evaluate()` unlocks `up:<id>`). Tests check that nodes don't overlap and are adjacent to their parent.
    - **The seed:** everything grows from **Initial Weights** at the centre (0, 0), 1 XP and one level (+5% sprint strength). It is drawn as the core's diamond (`.tree-node.seed`).
    - **Sparse by design:** every node has 1–3 levels. The ring around the seed costs 4–8 XP with 1–2 levels, the next ring has some one-level nodes, and 3-level nodes only start further out. Each node costs more than its parent. The roots are the basics, so early progression is sprint strength (GPU Cluster), one or two more sprints and less wait (Investor Funding → Faster Chips), and better XP (Bigger Datasets, `xp` stat → `xpMult`). Mechanics such as the sweet spot, luck and automation come after (the old "see further ahead" nodes were dropped: the view didn't help the way people play). More strength comes from tiers further out (GPU Cluster → Bigger GPU Cluster → GPU Supercluster), not from stacking levels. The UI shows only nodes you can buy and, as red locks, the next step past them; the rest stay hidden. A first return buys about one node. Tests enforce the shape.
    - **Mystery:** a locked node shows only a lock. Its detail reads "???" and "Unknown research", and names only what it grows from. **Secret nodes** (`secret: true`: Batch Normalization, Data Augmentation, Warm Restarts) never show, not even as a lock, until their parent is owned. Add more secrets to reward exploring.
    - The tree must not get `will-change: transform`: the browser would cache it as a bitmap at 1× and blur it when zoomed.
    - **Fixed cells:** nodes sit at `tree.{x, y} × --cell` px around the centre of `#treeViewport` (`placeNode`, `treeCell()`; `--cell` is 112 px, 84 on phones). Nothing is laid out from what's visible, so a new unlock appears in place and nothing else moves. The branch names are pinned to the view's edges.
    - The tree sits in `#treeViewport`, a camera you can drag (pan), wheel or pinch (zoom about the pointer) and control with +/−/reset buttons (bottom-left: the minimap covers the bottom-right); double-click empty space resets it (`treeCam`, `zoomTreeAt`). The view is remembered (`localStorage['agiTreeCam']`). A drag of 5 px or more swallows the click, so dragging across a node never selects it.
  - The node-detail panel is rebuilt only when its node, state or level changes: `render()` runs every tick, and replacing the button mid-click swallows the click. Buying keeps the popup open while the node has levels left (the next price lands under the pointer) and closes it after the last; the buy click stops propagating, since the rebuild detaches its button and the "click on empty space closes" handler would otherwise fire.
    - To add a node: an `UPGRADES` entry with `tab: 'training'`, a free grid cell next to its parent, an icon and a `boost` (stats in `TREE_STATS`).
  - Progression is bought with XP in the skill tree. GPU Cluster adds strength, Faster Chips cuts the wait, and Investor Funding adds training sprints per run (the base is 1, the launch only). The Auto-Trainer appears after a Transcend.
  - Push strength comes from upgrades, skills and `sqrt(globalMultiplier)`, then the sprint's zone and luck (`sprintStrength`). **Never tie it to Intelligence**: skills grant Intelligence, so the loop runs away (tested).
  - The engine owns the economy (`PATH`, `rollCost`, `payRoll`, `rollXp`, `finishRoll`, `learnSkill`); `training-path.js` owns the physics; `game.js` runs rolls, follows the ball with the camera and draws the trail.
  - Only `path.learned`, `path.best`, `res.xp` and `stats.rolls` are saved; an interrupted roll is simply lost.
  - Simulates while the page is open, never offline. Off screen (in the rack, the lab or the facility), a run in flight still finishes and the Auto-Trainer keeps starting new ones (`runsInBackground`); otherwise the loop sleeps.
  - **Lanes:** the Training Cluster's first three blade columns are a `canvas.lane` (`drawLanes`, every run-loop frame, on a 50 ms timer while the rack or facility is on screen, and after each camera refresh), in the rack and in its facility camera copy. Before the Auto-Trainer it is a monitor that **only shows what runs have seen**: the stretch up to the furthest point reached (the record, or the run in progress), scaled to what's known, with a dotted floor and `?` beyond (NO DATA before the first run). The seen part is dimmed, with a scan sweeping it every `LANE_SCAN_SECONDS` with a fading trail and a bright head on the line, and the best run marked (static under reduced motion). With the Auto-Trainer it goes live and follows the ball. Each cleared stretch adds a two-column lane (newest first, up to `MAX_CLEARED_LANES`) where a ball crawls along that stretch: the section automating itself (`buildTrainingArt`). `runLanes()` is 1 for now; concurrent runs will add lanes, each drawing its own ball.
  - Planned (design doc): opposing forces as special terrain that pushes the ball back, and prestige buffs along the trail. Add them as terrain data, like rolling hills.
  - Planned (much later in the tree): **launching off the line**, a jump that clears several hills at once, and **clearing more than one skill hill in a run** once the player is overpowered (the trail would continue into the next stretch after the roll-out). Gate both deep in the late game. 
  - **Text style everywhere:** skills (`SKILLS`, plus `FRONTIER_QUIPS` for generated ones) and every upgrade have a `flavor` too. It always comes **after** the plain effect (lab cards, node detail, the Skill learned card, the log), so players who only want the numbers read them first. It shows in italics (as a `#` comment in the software terminal).
  - **Node text:** every training node has a `flavor` (a one-line quip, ≤ 70 characters: straightforward, quippy or funny, e.g. Investor Funding: "Dad lent you $100. Don't tell Mum.") and an `effect` (the plain bonus, ≤ 80 characters, e.g. "+1 training sprint per run"). The node detail shows both. Tested.
  - **Framing:** the player is an AI research team pushing a model to its limits. Pushes are **training sprints** in everything the player reads (code keeps `push`/`pushes`). Upgrade names are AI-lab terms (Better Optimizer, Smoother Loss Landscape, Hyperparameter Search, Bigger Datasets, Eval Dashboards…) with plain effect text ("Training keeps its momentum longer").
  - The ball is drawn centred on the line, riding it like a bead on a wire.

## Screen layout

Everything grows as it unlocks, and locked things never say what they are: a sealed placeholder (`???`) hints that more is coming where that means something (rooms, bays, tree locks). Keep it that way when adding content.

**Layout stability:** players should find things where they left them. Every panel has a reserved home: new things fill reserved space or grow into empty floor, never insert above or before what's there, and nothing resizes because of a click. Lists that grow scroll inside their panel; items never vanish from under the pointer (investor offers keep their slot; a finished one-time card only leaves after you bought it, with an animation); text that changes length is clipped to one line (`room-goal`, action automation lines, top-bar numbers keep a minimum width). One-off reveals may extend the layout outward. Check new UI by recording panel rects before and after a purchase (`lab2.js`-style Playwright check).

**Information grows with the game:** show only what matters at this stage (top-bar chips, supply cells, stations, automation lines appear when they mean something), and add detail as systems open rather than all at once.

- **Top bar:** resource and attribute chips (`data-show="<unlock key>"` hides a chip until it matters; see Reveals), the phase bar and the Journal button.
- **Names:** the zoomed-out view is called **Surveillance** everywhere the player reads it ("← Surveillance"). The code still calls it `facility`.
- **Minimap** (`#minimap`, `renderMinimap`/`MINIMAP` in `game.js`): a titled microchip floating over the bottom-right corner (196 px, slightly translucent; no gutter, so content keeps the full width, and the lab and R&D leave scroll room under their last row; on phones only its "⌂ Surveillance" title shows), once the server room exists. Each open room is a block wired to a centre via, the server room's bays are cells inside its block, and the next sealed areas are dashed outlines. It gains blocks, traces and pins as areas open. The title and the chip itself (body, edge, pins) go to Surveillance, and hovering any of them lights the whole chip. Clicking a block calls `jumpTo()`: a quick fade straight there, bays included. "You are in: …" sits under it.
- **Surveillance** (`#facility`, the zoomed-out floor plan), laid out like the minimap's chip: wings across the top, the lab left (two columns wide), the server room tall on the right, R&D along the bottom, on a die with pins (grid areas on `.facility-plan`). One tile per room in `ROOMS` (`game.js`): Lab, Server room, R&D, then Boardroom, Signals room and Mirror room (phases 1–3, not built yet). Unlocked rooms show live status. The next `SEALED_ROOMS` (2) locked rooms show as anonymous "Sealed wing" tiles, and the rest aren't drawn, so the plan grows. Clicking a tile zooms into the room (`zoomIn`/`zoomOut`, Web Animations API). The facility and rooms share one grid cell in `.stage` so both are on screen during a zoom. Each room's "← Facility" button zooms out and pulses while a newly opened room is unvisited (`localStorage['agiRoomsSeen']`). The current view is kept in `localStorage['agiRoom']`. A new room is a `ROOMS` entry plus a `.room[data-room=id]` section.
- **Facility cameras:** each open room in `CAMERAS` (`game.js`) has a live feed on its tile: a scaled-down, inert copy of the room (`snapshot()` strips ids and `data-facility`/`data-bind`/`data-next`, and drops the `room` class and the room bar). It refreshes every second while the facility is on screen, and once more just before a zoom-out. New hardware, opened bays and automation show up there without extra code. Code that finds bays must search inside `#bays`, never the whole document, or it may hit a camera copy.
- **Navigation:** every screen is a frame with its way back *inside* it, top-left. Going home is the big jump: a filled green **⌂ Surveillance** pill (`.home-button`) in every room bar, and in a bay as a breadcrumb: `⌂ Surveillance / ← Rack / Training Cluster` ("← Rack" is the small step). The server room's bar lives in the hub, so it hides with the hub when a bay opens.
- **Goals live in the title bars:** there's no global goal line. Each bar shows its own next unlock (`goalFor(place)`, `data-bind="goal.<place>"`): the lab its next milestone, the server room its next sealed bay, the bay its next skill, R&D its Transcend, Surveillance its next sealed wing. Sealed things are never named.
