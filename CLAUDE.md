# The Path to AGI

Browser-based incremental (idle/clicker) game. Vanilla JS, no build step, no runtime dependencies.

## Commands

```bash
python3 server.py            # http://localhost:8000, no-cache; add --no-browser in headless envs, or pass a port
node --test                  # engine unit tests (Node 18+, no install needed)
```

Open the debug panel (`debug-panel.js`, which talks only to `AGI.debug`) by tapping the small terminal icon beside Journal (works on a phone and inside the artifact), with `/?debug` or `#debug` (only a `#hash` reaches an artifact), or with <kbd>`</kbd>; it's remembered per device, and its × closes it:
- **Save** (first, so it's easy to reach): save now, or start over (wipes the save and all screen state: open bay, result card, room visits, tree view).
- **Resources / Attributes:** add any amount (XP included; added CP counts as earned this run, so it moves the hardware reveals and shipping).
- **Per second:** a flat amount of any resource (Insight included) added every second of game time, on top of production (`AGI.debug.income`; follows game speed and Simulate; debug CP counts as earned). 0 turns it off.
- **Rate multipliers:** CP, DP, RP and XP/s (cleared stretches).
- **Time:** simulate N seconds, or set a **game speed** (1×/2×/5×/20×) for both the economy and the training physics.
- **Progress:** learn the next skill, reach a phase, or unlock everything.
- **Versions:** add a version without resetting (+10 Insight; opens R&D and the legacy nodes), ship the next version now, or max every legacy node; open the challenges, beat the running one, or make Transcend ready (the Singularity).
- **Lab:** fill, finish or clear investor offers; meet every automation's "by hand" gate; +10 of every hardware tier (watch the cabinets merge); +1 of every visible lab upgrade; a test line in the lab log.
- **Server room:** +50 automated laps on every cleared leg; set the frontier record to 90%; reset room visits and the cabinets' order.
- **Power-ups:** Breakthrough and Paradigm Shift (on your next sprint), Max Effort, Crunch, Bullet Time, Flow and Lucid Dream (on the ball in flight, else your next sprint), System prompt (your next release), Viral (the next run's end).
- **Training:** finish the run; **Fling the ball** (throws it into the air: flights, bounces and the late-leg camera); **Test summit** and **Test near miss**, which put the ball on the skill hill's climb just above or below the exact speed needed (found by simulating a copy of the run); max the skill tree; toggle the Auto-Trainer; reset the tree view.
- A live state view.

## Layout

| File | Role |
|---|---|
| `engine.js` | **All game rules and data**, no DOM. UMD: `window.AGIEngine` in the browser, `require()` in Node |
| `training-path.js` | Training Path physics: trail geometry and a fixed-step ball sim (`window.TrainingPath` / `require()`). Pure: no DOM, no clock, no randomness |
| `game.js` | `window.AGI`: builds the UI from engine data, input (hold-to-repeat: fires on press with no delay, then every `HOLD_REPEAT_MS` 250, 4 clicks a second, a comfort option rather than a turbo), 100 ms loop, render, save/load/export, and the Training Path canvas view |
| `sfx.js` | `window.SFX`: every sound, synthesised with Web Audio (no files): one-shots by name (`SFX.play`), the rising sprint-meter tone (`SFX.charge`/`chargeStop`), master volume from the Sound setting; silent until the first gesture. `game.js` plays lab sounds always and training sounds only while the trail is visible (`sfx`/`trailSfx`) |
| `debug-panel.js` | Dev tools; talks only to `AGI.debug` |
| `index.html` | Static shell; dynamic parts are generated by `game.js`, values bound via `data-bind="key"` (see `bindValue`) |
| `styles.css` | All styles. "Night survey" single dark theme: tokens on `:root`, fonts Chakra Petch (display), Atkinson Hyperlegible (body), JetBrains Mono (numbers). Screen-size tiers at the end |
| `tests/*.test.js` | `node:test` suites for the engine and the Training Path |

## Architecture rules

- **Content is data.** Actions, tabs, upgrades, milestones, achievements and phases are arrays in `engine.js`. Add an upgrade by adding an `UPGRADES` entry (`scale` = repeatable, `max: 1` = one-time, `grants` = attributes per level, `requires`/`unlock`/`hint` = gating) and, if it affects production, a term in `derive()`. The UI picks it up automatically.
- **Derive, don't store.** Production rates come from `derive(state)` using upgrade levels; phase comes from `phaseIndex(state)` using attributes. Only store what the player earned (resources, attributes, levels, unlocks, achievements, stats).
- **Unlocks are sticky.** `evaluate()` records milestone/upgrade unlocks in `state.unlocked` and achievements in `state.achievements`; it returns what changed so `game.js` can log/toast it once.
- **Saves.** `localStorage['agiGame']`, versioned (`SAVE_VERSION`). `migrate()` sanitizes any input (wrong types, negatives, unknown ids) and converts the original v1 format. If you change the state shape, bump `SAVE_VERSION`, extend `migrate()`, and add a test. **Save safety:** one tab plays at a time (`claimTab`: a tab that opens the game claims it on a `BroadcastChannel`, the newest wins; the others save once, stop ticking and saving, and offer **Use this tab**, which reloads; two tabs used to write over each other). The handover message carries the save itself (`json`): another tab's storage can lag behind the channel, and the new tab read the save from before. A good save is copied to `agiGame.bak` on load, every 10 minutes and before an import; an unreadable save is kept in `agiGame.corrupt` and the backup restored (else a new game), with a dialog holding the raw text. Import shows both games' summaries (`saveSummary`) and warns about a newer save version; **Restore backup** (Settings) swaps the game and the backup.
- **Automation converts, it never creates.** The Auto-Collector (the "Data crawler") spends CP for DP and the Research Assistant spends CP and DP for RP, at the manual action prices. Each is a **scheduled task** (`TASKS`, `state.tasks`, save v5) with an on/off switch and its own share of each second's production, "dedicated compute" (`taskShares`, defaults 40% and 30%; research takes the same share of DP). Shares are taken in order and never add up to more than 100% (`setTaskShare` caps a slider at what the others leave), so automation never touches the stockpile and compute never falls. Over its share a task slows down (`derive().tasks[id].speed`, `autoThrottled`). The Auto-Trainer is a task too (switch only, `autoTrainerLevel`), but its switch lives in the server room, where you watch it (see Auto-Trainer); its Scheduled tasks row only reports. Only hardware creates CP. The top-bar rates are net (`cpNet`, `dpNet`).
- **Automation is earned** (`AUTOMATION`, `automationGate()` in `engine.js`): each machine that does a job for you needs proof you've done it by hand (a stat count) and, for the bigger ones, a training skill. Graphics Card (the first generator, id `cpu`): 40 computes by hand and the click tool grown to the Server Rack (level 5, `CPU_AFTER_CLICK_LEVEL`; the click tool shows first, at 15 computes), so you build up your desk before automating. Collect Data itself only appears at 5 CP/s of passive compute (milestone `action:collect`), and Research after the first skill plus 50 paid training sprints (`action:research`, `RESEARCH_SPRINTS`, counted in `stats.skilledSprints` by `payPush` once a skill is learned; older saves past the first skill estimate 2 per run; costing 200 CP and 40 DP). After the first shipped version Research stays open (and the investors with it). Compiler Optimizations at 10 Server Clusters, so compute options arrive one at a time. Auto Data Collector: the first skill (Pattern Matching) plus 40 collections by hand (`stats.collects`; the server room already needed 40), so data automation arrives with the first skill. Research Assistant: Language Modeling plus 50 research runs by hand (`stats.researchManual`). The Workbench's compute line shows the desk's progress ("desk 3/5") until it's built, and gates name the skill they wait for. Hand counts carry across versions for the gates (`stats.collectsEver`, `researchManualEver`): a gate met once stays met, so a new version doesn't repeat 40 collections and 50 research runs by hand (the version's own counts still reset, for the reveals and investor tasks). Automation starts slow (0.2 and 0.1 jobs/s per level) and each level costs much more (×1.5 / ×1.55). Later automation can also be gated behind stations, rooms or prestige upgrades.
- **Hardware is a spaced-out generator ladder**, like most incremental games: each tier (`cps` on its `UPGRADES` entry, summed over `HARDWARE` in `derive()`) costs 20× the last and gives about 6.7× the CP/s, so it pays back 3× slower (30 s, 90 s, 4.5 min, 13 min, 40 min, 2 h for one unit). When a tier appears, the one below stays the better buy for about eight more units before the new one takes over; the old 12× ladder made each tier stale as soon as the next showed up. All cost ×1.15 per unit, and a tier's output doubles at 25, 50 and 100 owned (`HARDWARE_DOUBLINGS`), which makes older tiers worth topping up again. A tier shows up only once you own ten of the tier below and have earned its full price this run (`tierReady`; the top two also need their phase). **Cards carry the numbers, not the descriptions:** every lab card has a live line (`yieldText`): hardware shows CP/s each (every multiplier in; `derive().hardwareRates`), never the next doubling; other cards show the one number they change, as "now → after the next level" (the upgrade's `shows`: `click`, `collect`, `research`, `hardwareMult`, `autoCollect`, `autoResearch`; attribute upgrades show the attribute totals). **The click tool** is one repeatable upgrade (`keyboard`) that grows through `CLICK_TOOLS` as you level it, your desk first, one item per level at its own price (`costs` on the upgrade: Desktop Tower 25, Mechanical Keyboard 45, Gaming Mouse 45, Monitor 75 CP, each +0.25 per click, so a click reaches 2 CP; then the Server Rack, 100 CP, +1), then ×1.32 per level through Macro Pad → Summer Intern → Team of Interns → Crowdsourcing Platform → Click Farm → Robotic Clicker Arms, each stage adding more CP per click per level (`clickToolPower`). The card's name and flavour follow the stage (`upgradeName`/`upgradeFlavor`), and its line never names the next one (growing into it is a surprise; it goes to the log). Software multipliers: Compiler Optimizations and Kernel Fusion (+50% hardware each); NLP ×1.5 and Computer Vision ×2 Data crawler speed. Tested: the ladder's ratios, the doublings, the reveal rule, and that Server Cluster no longer touches clicks.
- **Achievements** (31: the early list plus a long-term one for versions, challenges, Transcend, flights, tokens, investors, replays and totals) are recognition only, with no production bonus (they used to add +2% each, which made a click 1.02). Versions (Insight, `globalMultiplier`) are the only global multiplier.
- **Hand actions pay whole numbers:** a click, a collection or a research run by hand adds only flat amounts (the click tool, Data Processor, the algorithms, skills' `click`/`collect`/`research`). Percentage bonuses (skills' `dp`/`rp`, Insight) go to what runs by itself: hardware, the Data crawler and Research Assistant (`autoDpPerCollect`, `autoRpPerResearch`) and training XP. A click never reads 2.3 DP or 3.60 CP (tested).
- **Supply chain (the lab feeds training):** the lab produces compute and data, training sprints spend them (the late cost ramp makes income limit charges: about half of the sim's sprints fall short of full), learned skills boost the lab and unlock its automation, and every lab currency also buys training: data the **Training Data Pipeline** (software, endless, +8% sprint strength per level, from the warm-up skill: data had no use until Pattern Matching), research the algorithms' training effects (Machine Learning +10% XP, Deep Learning +15% strength, Reinforcement Learning +1 sprint, Transfer Learning +25% XP: lab upgrades may carry a `boost`, summed with the tree's in `treeBoosts`) and **Published Papers** (endless, research only, +10% training XP per level), and investors pay in training XP. Before this, the best play was to ignore the lab after the first few minutes (a sim with more lab time reached General AI later). The Training Cluster bar shows the lab's supply.
- **Tree pricing:** a node's first level always costs more than its parent's last level (tested), so finishing a node is never worse value than skipping ahead (Lucky Break 2 used to equal Serendipity 1). **No repeats down a path or across siblings:** a node never boosts the same stat as the node it grows from, and nodes growing from the same node never share a stat either (both tested), so each step and each choice feels new. **The shape stays mirror-symmetric:** the inner ring branches both ways off Power (Batch Normalization right, Smoother Loss Landscape left) and Recursion (Warm Restarts left, Data Augmentation right) while Momentum and Precision run straight, because one side node per arm, each bent the same way round, read as a swastika. Paths: Power runs GPU Cluster (strength) → Fast Charging → GPU Supercluster (strength) → Max Effort → Exascale (strength) → Fusion Reactor (breakthrough power) → Dyson Swarm (strength), with Liquid Cooling (drag), Quantum Accelerator (Max Effort power) and the luck nodes off to the side, and Max Effort a single level so it doesn't wall off the strength behind it; Momentum alternates drag and hills; Recursion's two columns alternate sprints and wait (Bridge Round, Strategic Partner, Hiring Spree, Round-the-Clock Ops); Initial Weights lowers the rolling hills (it used to cut the wait between sprints, which does nothing while a run has one sprint).
- **Data stays data:** only the Data Processor raises data per collection; NLP and Computer Vision make the Data crawler faster (×1.5, ×2) and grant no Intelligence (Intelligence comes from training and the algorithms; Self-Improve, a direct +5 Intelligence that skipped the Training Path to General AI, is gone).
- **Early pacing (nothing before it makes sense):** the click tool (15 computes) → your desk, one item at a time → the Graphics Card after the Server Rack → Collect Data at 5 CP/s (and the software terminal and lab log with the first data) → the server room once you've collected data 40 times by hand and built a stockpile (100 CP, 40 DP held; `module:path`), so data matters before a skill automates it → Server Cluster only after the first training run (`tierReady` and `stats.rolls`), so it doesn't arrive with the server room → Research 50 training sprints after the first skill: research is the vehicle for bigger projects, and it brings the investors, whose offers point the player toward shipping the next version (a `Research funded` callout says so).
- **Reveals:** top-bar chips appear only once they matter (`REVEALS` in `engine.js`: `seen:dp`, `seen:int`, `seen:cre`, `seen:awa`; the phase bar shows with Intelligence). Each is introduced once with a toast and a log line. XP lives in the Training Cluster bar, not the top bar. The Software station opens with `seen:dp`.
- **The lab splits by resource:** the hardware bench is all compute (the generator tiers, the click tool, Compiler Optimizations, Kernel Fusion), the software terminal is all data (Data Processor, Auto Data Collector, NLP, Computer Vision), the research wall holds research (Research Assistant, the algorithms and Published Papers), and investors pay in training XP. Tested.
- **Investor projects** (`engine.js`, save v3): investors come with Research, so once the Training Cluster runs and Research is open, offers arrive every 2.5–5 min of game time (`PROJECTS`, at most 3), each an investor, an optional task with a deadline (`PROJECT_TASKS`: computes or collects by hand, finish runs, clean sprints, earn CP, research), and a reward in training XP (`PROJECT_REWARDS`: +50% training XP for 5 min, training XP ×2 for 3 min, or a training grant of about 1.5 or 4 full stretches). Older saves' compute, data, research and sprint boosts still apply until they run out. Progress counts from when the offer arrived. Tasks grow with the frontier (`runs` and `clean` by skills learned; `tokens` and `flights`, flights of `LONG_FLIGHT` 10 m or more counted in `stats.flights`, from act two; `replays`, cleared skill hills crossed on replays, from four skills; hand collections only before the crawler). Claim when done (`claimProject`), or ignore and it expires; a finished offer never expires, and a badge on the Lab's Surveillance tile and the run view's lab supply counts the ones waiting (`[data-ready]`). Boosts also reach passive leg XP, and grants ignore a running boost (`grantMult`: claiming ×2 first doubled them). Boosts multiply in `derive()` via `projectBoosts`. Seeded by `projects.seq`, so tests are deterministic. The lab shows them in the supply strip, with active boosts and timers; rows are rebuilt only when the offers change.
- **An active game: no offline progress.** Nothing is earned while the page is closed or the tab hidden (`tick()` returns while `document.hidden`; a long gap, such as the machine asleep, is skipped with a log line). There is no offline setting and no While you were away card (save v11 drops `settings.offline`; `applyOffline` is gone). Passive income (hardware, automation, cleared legs) runs only while you're playing.
- **Quality of life (what players of the genre treat as table stakes):** bulk buying (a ×1 / ×10 / Max switch in the lab's bar, `#bulkBuy`, remembered in `localStorage['agiBulk']`; repeatable lab cards only, one-time cards and the tree buy one: `bulkCost`, `maxAffordable`, `buyMany`); every unaffordable lab price says how long until it's affordable at the current net rates (`etaText`, on a small second line inside the price button with the ×N); number notation (standard suffixes, scientific or engineering: `settings.notation`, `E.setNotation`); a sound volume and a screen-shake switch (`settings.sound`, `settings.shake`; shake also gates the flashes and jolts; save v9); **text size** 100/115/130% (`settings.textSize`, `TEXT_SIZES`: it multiplies the large-screen zoom, `--zoom` = `--ui-scale` × `--text-size`, and `uiScale()` includes it); **Reduce animations** (`settings.calm`, `body.calm`, read by `reducedMotion()` like the system setting); **idle** (`watchIdle`): a minute without input or the window in the background pauses the decorative CSS loops (`body.idle`, toasts excepted) and refreshes the camera feeds a fifth as often (they were most of the idle CPU); distance marks on the trail tied to the world (faint verticals, a tick on the ground every round number of metres, `postStep`, labelled along the bottom like a ruler: on the ground the labels sat on hill faces), so speed reads on the flat (the ball carries no spin mark); a badge on every Upgrades button while XP can buy a skill-tree node (`treeReady`, `[data-ready]`); hotkeys in the Training Cluster (U swaps the trail and the upgrades, R trains again; Space/Enter sprint; Esc backs out; listed in Settings); and per-run stats on the result card (top speed, and in act two the longest flight and its height), with all-time bests kept across versions in `stats.topSpeed`/`bestFlight`/`bestHeight` and in the Journal's Stats.
- **The game is played as a claude.ai artifact** (also on the owner's phone), so it must run in that frame as it would standalone. The frame refuses `alert`/`confirm`/`prompt` (dialogs are in-page, `openDialog`), downloads (Export shows a code to copy) and query strings (debug also opens with `#debug` or the icon), may refuse storage (every read and write goes through `storageGet`/`storageSet`, and the game plays without it) or a `BroadcastChannel` (the tab lock gives up quietly), and clipboard writes can reject (always caught). **Saves are per device on purpose** (the owner chose that): the phone and the computer are separate games, and Export/Import moves one. **Republishing while it's open:** the viewer swaps in the new version, so `init` registers `window.claude?.hot?.snapshot` to save and hand the save across, and `load()` prefers `window.claude?.hot?.data.save` (tested: progress survives an update with storage wiped). **Keep the screen on** (Settings, per device in `localStorage['agiAwake']`, on by default on touch screens): an active game earns nothing while a phone sleeps, so a screen wake lock is taken on the first touch and again when the page is shown; hosts that refuse it are ignored. Test the artifact build in an artifact-like frame (the platform's skeleton around the page, in a sandboxed iframe, with and without `allow-same-origin`).
- Keep `engine.js` free of DOM/`window` so it stays testable.
- **Training Path** (how the AI learns):
  - The trail is a series of stretches. Stretch k runs from a checkpoint to **skill hill k** (fixed, grows each stretch). Cresting it learns `skillAt(k)`: attributes plus a permanent bonus summed in `derive()` via `skillBonuses()`.
  - **The warm-up (leg 0, Tokenization):** a 2 m flat run to a 3 cm hill with no rolling hills (`TUTORIAL` in `training-path.js`; `legMetres` mirrors it), so the first summit comes on the first run or two: one full sprint or two medium ones crest it, two weak taps don't (tested). It teaches +10% sprint strength and grants no attributes. Every later leg k is the old leg k − 1 (the geometry uses k − 1), and Pattern Matching's leg is 9 m instead of 10, so Pattern Matching lands about 15 runs in (the human-model sim: run 15–18; it was 20–30 runs to the first skill before). Gates that meant "the first skill" mean Pattern Matching (skill 1, `FIRST_REAL_SKILL`): Research's 50 sprints count from it, the Auto Data Collector needs skill 2 and the Research Assistant skill 6 in `AUTOMATION` terms, the Training Data Pipeline opens after it and Lucky Break at 3 learned; push costs and Insight ignore the warm-up (`pushCost` uses the leg − 1, `prestigeGain` skills − 1). Save v8 moves older saves past the start one leg along (`learned` + 1, laps and best runs shifted).
  - Each **roll** starts at the checkpoint over **random rolling hills** (`rollingHills(k, seed)`, new seed per roll from `rollSeed`). The roll ends only when the ball rests with no pushes left (or rolls back past the start): **a skill hill never cuts a run short.** Distance earns **XP** (`finishRoll`), and the furthest roll is the stretch record (`path.best`).
  - **Flat start:** nothing is behind the start line (no wall, no previous hill), and a ball that gains no new ground for `STALL_SECONDS` 8 with no sprints left ends its run whatever keeps it moving (a strip once pumped a spent ball forever), and a ball that rolls back past it (`ROLL_BACK`) with no sprints left ends the run (with sprints left the line is a soft bumper, `BUMPER` 0.3 of its speed back, a `bump` event: a weak launch used to roll back over the start before the wait was up, ending a third of early runs with a sprint unspent) (`end` with `rolledBack: true`, progress 0, paying for half the furthest distance reached; the card says "Rolled back to the start"). The drawing is flat there too, except in the post-skill overview.
  - Once the ball lacks the energy to clear either neighbouring hill it is "trapped" and is braked near the floor of its dip only (`TRAPPED_DAMPING` 6 where the slope is under 0.08), so it swings freely on the slopes and bleeds speed at the bottom like a pendulum, settling about 1.1 s after it's stuck (median). Braking it on the slopes too made it roll back down and come to rest as if through syrup (tested). Full momentum otherwise.
  - Pushes add a fixed amount of *energy* (pushing against a backward roll is wasted), and drag is partly quadratic. So saving pushes to rescue a stalling ball beats firing them early. Tests guard this; keep it true when tuning.
  - **Act two thrusts instead** (from `LATE_LEG`, by the leg the ball is on; `thrustLeg` in `game.js`): holding fires a jet behind the ball (`roll.thrust`, energy per second; `burn()` in `training-path.js`) instead of charging a sprint, so the late game is about keeping momentum up, like a rocket in Learn to Fly. The run's sprints are its **fuel** (`pushesLeft`, now fractional): one sprint's worth burns in `BURN_SECONDS` 0.6 at full thrust (a hot, short burn: at 1 s, slow thrust up the skill walls lost its energy to drag) and delivers `PATH.thrustEfficiency` 1.25× a full sprint's energy. It is paid as it burns (`E.burnCost`/`payBurn`: that share of a full sprint, no whole-number floor). On the ground it adds energy along the line; in flight it drives the ball forward (not along its heading: on the way down that drove it into the ground) and holds it up with `THRUST_LIFT` 0.7 of flight gravity, flying freely and planning its landing again once the jet stops. **Slipstream** (the prompts' replacement, since act two has no meter): every `PATH.slipstream` 0.25 unit of fuel burned in flight pays like a clean prompt (XP now and the run bonus; `slipstream()`, merged pops, "Slipstream run bonus" on the result card). Each unit of fuel that lights rolls the sprint luck (`lightBurn`: a breakthrough or Max Effort makes that unit stronger, a crunch makes thrust free for its seconds via `roll.thrustFree`, flow as before; Bullet Time stays act one's). The meter becomes the fuel tank ("Fuel 7.2 / 12 · full thrust … per second", `.charge.fuel`), the pip being burned drains, the button reads Hold to thrust / Thrusting… / Out of fuel · hold to dive, and the ball trails a flame and exhaust puffs left in the world behind it (`drawThrust`, hotter for a lucky burn). With the tank empty a hold is the tuck. The ACT II banner shows the first time a run is on act two's trail ("Hold to thrust"). The Auto-Trainer thrusts there: from rest and below `AUTO_THRUST_SPEED` 1.5 m/s (level 1), up climbs it won't make (2), and on the way down in flight (3). Tested: fuel burns at one unit per `BURN_SECONDS`, a crunch burns none, an empty tank ends the run at rest, thrust in flight stays aloft longer and goes further. Pacing (human-model sim, which thrusts from rest, when slow or stalling, and on the way down in flight): skill 8 about 3 min after General AI's 7, then 9 at 40–47, 10 at 43–52, 11 at 56–69, 12 at 75–85, 14 at 96–114, 16 at 133–150 min (sprints: 9 at 49–52, 12 at 67–73, 16 at 121–132), so late act two runs 10–15% slower; without slipstream it was half as fast (the run bonus from prompts carried late distance XP).
  - **Pushing is hold-to-charge** (act one). A meter sweeps up and down while the button (or Space/Enter, or the canvas) is held, and release fires at that fraction of `pushPower`.
    - Every push costs CP and DP by `pushCost(s, charge)` (∝ charge², ×`pushCostScale` 1.4 per stretch for the first three, then ×`pushCostLate` 1.9 from `pushCostRampFrom`, so sprints keep leaning on the lab's income later on: at a flat 1.4 a full sprint cost about 5% of a second's compute by the hour mark and never limited a charge), so passive income gates how hard you can push. The meter only reaches `affordableCharge()`.
    - Each push has a **bonus zone** (`bonusZone(seed, index, width, perfect, system)`, centred between 50% and 85%), and `zoneHit()` classifies a release as `'clean'`, `'perfect'`, `'system'` or none. **Players read these as prompts:** a *clean prompt* (the zone), a *super prompt* (the perfect spot, from Prompt Engineering) and a *system prompt* (a 1% sliver inside the super prompt, legacy System Prompt, worth `systemMult` 50 clean prompts). Code keeps `clean`/`perfect`.
    - A clean prompt banks a small flat amount of XP at once (`grantPushBonus`, scaled by the release charge over `PROMPT_CHARGE` 0.575, the zone's average centre, 0.3–1.5×: weak taps into low zones out-earned full sprints and skipped the launcher) and adds `cleanRollBonus` to the roll's distance XP; a super prompt counts as `perfectMult` clean ones (`cleanUnits`). This is the trade-off: steady XP from the zone, or full charge for distance.
    - **Prompts grow in order:** first the clean prompt (Hyperparameter Search: power; Benchmark Prizes: rewards; Prompt Templates: the zone 15% wider per level, the only widening, so it stays a skill; Prompt Tuning: `zoneBias`, zones sit higher on the meter, where sprints are stronger). The zone can land anywhere from 25% to 90% of the meter (`bonusZone(…, bias)`). Then super prompts: Prompt Engineering adds the spot, Few-Shot Examples its effects (+20% strength, +1 clean prompt's worth per level, `perfectUnits`), and only then Chain of Thought widens it (+40% per level, dear), so super prompts stay rare and rewarding. Upgrades make hitting them *pay*: a sprint's strength is `sprintStrength(s, fraction, kind, breakthrough, maxEffort)`, ×`cleanPower` in the zone (Hyperparameter Search +20%), ×`perfectPower` on the super prompt (+30% more) and ×`systemPower` on the system prompt. Benchmark and Leaderboard Prizes (flat XP), Curated and Hand-Labelled Data (run bonus). The meter shows the boosted strength while you're in the zone. Tested.
    - **No charging during the wait:** while the cooldown runs (or a breakthrough winds up) the meter greys out (`.charge.waiting`), the button counts down ("Next sprint in 1.2 s") and is disabled, and pressing does nothing: a sprint charges only when it can fire (`readyToFire`), so there's no queueing. A press during the wait never queues a sprint: holding through it used to start a charge the moment it ended, and letting go a beat later fired a tiny sprint by accident; a sprint takes a fresh press (on act two the held press is a tuck instead). The meter lives only under the trail (an arc over the ball, `drawChargeRing`, was cut as clutter). Every run plays out in real time (a lost run used to play out at 3× on screen: falling back at triple speed looked weightless). Bullet Time is the exception (sprints bank whenever). The breakthrough's sprint lands at once (`roll.push`) while the wind-up holds the run still, and the cooldown keeps counting through the wind-up.
    - **Fast Charging** (`charge` stat → `chargeHold`, seconds) holds the meter at the top of its sweep for a moment before it comes back down, so a full release is easier to catch; the sweep itself is always `CHARGE_SWEEP_MS` 1250 (it used to speed up, which made every timed release harder). ## Screen layout

Everything grows as it unlocks, and locked things never say what they are: a sealed placeholder (`???`) hints that more is coming where that means something (rooms, bays, tree locks). Keep it that way when adding content.

**Layout stability:** players should find things where they left them. Every panel has a reserved home: new things fill reserved space or grow into empty floor, never insert above or before what's there, and nothing resizes because of a click. Lists that grow scroll inside their panel; items never vanish from under the pointer (investor offers keep their slot; a finished one-time card only leaves after you bought it, with an animation); text that changes length is clipped to one line (`room-goal`, action automation lines, top-bar numbers keep a minimum width). **Short screens:** on desktops 900 px tall or less the reserved station rows shrink (330/290 px) so Scheduled tasks and the cabinets, where clicks show, come above the fold. **No stray scrollbars:** the top bar keeps one row from 1280 px (tighter chips and a shorter phase bar from 961 to 1440 px); a scrolling list that overflows by 12 px or less clips instead (`nearlyFits`, `.nearly-fits`, re-checked by a ResizeObserver before paint), lists clip while the lab makes room (`body.making-room`), camera copies never show scrollbars, and Surveillance fits the window on desktop; only genuinely long lists scroll (thin, themed). Check with a per-frame overflow scan while the lab grows. One-off reveals may extend the layout outward. Check new UI by recording panel rects before and after a purchase (`lab2.js`-style Playwright check).

**Reveals animate:** nothing pops in. Anything shown through `setHidden` that matches `REVEAL` (panels, stations, supply cells, chips, workbench jobs, tasks, cards, tree nodes, facility tiles) boots up (`revealIn`, `.reveal-in`, 1.5 s: a scan wipe with a bright edge, a flicker, a fading glow), never on load, in camera copies or under reduced motion. In the lab, what's already there **makes room first** (`makeRoom`, 750 ms: a snapshot before the change, then panels, stations, supply cells, jobs and tasks slide and resize from where they were, without scaling their text) and the new section waits until then to boot in. Show new UI with `setHidden`, not `.hidden =`, so it gets this.
