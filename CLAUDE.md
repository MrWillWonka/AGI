# The Path to AGI

Browser-based incremental (idle/clicker) game. Vanilla JS, no build step, no runtime dependencies.

## Commands

```bash
python3 server.py            # http://localhost:8000, no-cache; add --no-browser in headless envs, or pass a port
node --test                  # engine unit tests (Node 18+, no install needed)
```

Open `/?debug` (or press <kbd>`</kbd>) for the debug panel (`debug-panel.js`, which talks only to `AGI.debug`):
- **Save** (first, so it's easy to reach): save now, or start over (wipes the save and all screen state: open bay, result card, room visits, tree view).
- **Resources / Attributes:** add any amount (XP included; added CP counts as earned this run, so it moves the hardware reveals and shipping).
- **Rate multipliers:** CP, DP, RP and XP/s (cleared stretches).
- **Time:** simulate N seconds, or set a **game speed** (1×/2×/5×/20×) for both the economy and the training physics.
- **Progress:** learn the next skill, reach a phase, or unlock everything.
- **Versions:** add a version without resetting (+10 Insight; opens R&D and the legacy nodes), ship the next version now, or max every legacy node.
- **Lab:** fill, finish or clear investor offers; meet every automation's "by hand" gate; +10 of every hardware tier (watch the cabinets merge); +1 of every visible lab upgrade; a test line in the lab log.
- **Server room:** +50 automated laps on every cleared leg; set the frontier record to 90%; reset room visits and the cabinets' order.
- **Power-ups:** Breakthrough and Paradigm Shift (on your next sprint), Max Effort, Crunch, Bullet Time, Flow and Lucid Dream (on the ball in flight, else your next sprint), System prompt (your next release), Viral (the next run's end).
- **Training:** finish the run; **Fling the ball** (throws it into the air: flights, bounces and the late-leg camera); **Test summit** and **Test near miss**, which put the ball on the skill hill's climb just above or below the exact speed needed (found by simulating a copy of the run); max the skill tree; toggle the Auto-Trainer; reset the tree view.
- A live state view.

## Layout

| File | Role |
|---|---|
| `engine.js` | **All game rules and data**, no DOM. UMD: `window.AGIEngine` in the browser, `require()` in Node |
| `training-path.js` | Training Path physics: trail geometry and a fixed-step ball sim (`window.TrainingPath` / `require()`). Pure: no DOM, no clock, no randomness |
| `game.js` | `window.AGI`: builds the UI from engine data, input (hold-to-repeat: fires on press with no delay, then every `HOLD_REPEAT_MS` 400, 2.5 clicks a second, a comfort option rather than a turbo), 100 ms loop, render, save/load/export, and the Training Path canvas view |
| `debug-panel.js` | Dev tools; talks only to `AGI.debug` |
| `index.html` | Static shell; dynamic parts are generated by `game.js`, values bound via `data-bind="key"` (see `bindValue`) |
| `styles.css` | All styles. "Night survey" single dark theme: tokens on `:root`, fonts Chakra Petch (display), Atkinson Hyperlegible (body), JetBrains Mono (numbers). Screen-size tiers at the end |
| `tests/*.test.js` | `node:test` suites for the engine and the Training Path |

## Architecture rules

- **Content is data.** Actions, tabs, upgrades, milestones, achievements and phases are arrays in `engine.js`. Add an upgrade by adding an `UPGRADES` entry (`scale` = repeatable, `max: 1` = one-time, `grants` = attributes per level, `requires`/`unlock`/`hint` = gating) and, if it affects production, a term in `derive()`. The UI picks it up automatically.
- **Derive, don't store.** Production rates come from `derive(state)` using upgrade levels; phase comes from `phaseIndex(state)` using attributes. Only store what the player earned (resources, attributes, levels, unlocks, achievements, stats).
- **Unlocks are sticky.** `evaluate()` records milestone/upgrade unlocks in `state.unlocked` and achievements in `state.achievements`; it returns what changed so `game.js` can log/toast it once.
- **Saves.** `localStorage['agiGame']`, versioned (`SAVE_VERSION`). `migrate()` sanitizes any input (wrong types, negatives, unknown ids) and converts the original v1 format. If you change the state shape, bump `SAVE_VERSION`, extend `migrate()`, and add a test.
- **Automation converts, it never creates.** The Auto-Collector (the "Data crawler") spends CP for DP and the Research Assistant spends CP and DP for RP, at the manual action prices. Each is a **scheduled task** (`TASKS`, `state.tasks`, save v5) with an on/off switch and its own share of each second's production, "dedicated compute" (`taskShares`, defaults 40% and 30%; research takes the same share of DP). Shares are taken in order and never add up to more than 100% (`setTaskShare` caps a slider at what the others leave), so automation never touches the stockpile and compute never falls. Over its share a task slows down (`derive().tasks[id].speed`, `autoThrottled`). The Auto-Trainer is a task too (switch only, `autoTrainerLevel`), but its switch lives in the server room, where you watch it (see Auto-Trainer); its Scheduled tasks row only reports. Only hardware creates CP. The top-bar rates are net (`cpNet`, `dpNet`).
- **Automation is earned** (`AUTOMATION`, `automationGate()` in `engine.js`): each machine that does a job for you needs proof you've done it by hand (a stat count) and, for the bigger ones, a training skill. Graphics Card (the first generator, id `cpu`): 40 computes by hand and the click tool grown to the Server Rack (level 5, `CPU_AFTER_CLICK_LEVEL`; the click tool shows first, at 15 computes), so you build up your desk before automating. Collect Data itself only appears at 5 CP/s of passive compute (milestone `action:collect`), and Research after the first skill plus 50 paid training sprints (`action:research`, `RESEARCH_SPRINTS`, counted in `stats.skilledSprints` by `payPush` once a skill is learned; older saves past the first skill estimate 2 per run; costing 200 CP and 40 DP). After the first shipped version Research stays open (and the investors with it). Compiler Optimizations at 10 Server Clusters, so compute options arrive one at a time. Auto Data Collector: the first skill (Pattern Matching) plus 40 collections by hand (`stats.collects`; the server room already needed 40), so data automation arrives with the first skill. Research Assistant: Language Modeling plus 50 research runs by hand (`stats.researchManual`). Automation starts slow (0.2 and 0.1 jobs/s per level) and each level costs much more (×1.5 / ×1.55). Later automation can also be gated behind stations, rooms or prestige upgrades.
- **Hardware is a spaced-out generator ladder**, like most incremental games: each tier (`cps` on its `UPGRADES` entry, summed over `HARDWARE` in `derive()`) costs 20× the last and gives about 6.7× the CP/s, so it pays back 3× slower (30 s, 90 s, 4.5 min, 13 min, 40 min, 2 h for one unit). When a tier appears, the one below stays the better buy for about eight more units before the new one takes over; the old 12× ladder made each tier stale as soon as the next showed up. All cost ×1.15 per unit, and a tier's output doubles at 25, 50 and 100 owned (`HARDWARE_DOUBLINGS`), which makes older tiers worth topping up again. A tier shows up only once you own ten of the tier below and have earned its full price this run (`tierReady`; the top two also need their phase). **Cards carry the numbers, not the descriptions:** every lab card has a live line (`yieldText`): hardware shows CP/s each (every multiplier in; `derive().hardwareRates`), never the next doubling; other cards show the one number they change, as "now → after the next level" (the upgrade's `shows`: `click`, `collect`, `research`, `hardwareMult`, `autoCollect`, `autoResearch`; attribute upgrades show the attribute totals). **The click tool** is one repeatable upgrade (`keyboard`) that grows through `CLICK_TOOLS` as you level it, your desk first, one item per level at its own price (`costs` on the upgrade: Desktop Tower 25, Mechanical Keyboard 45, Gaming Mouse 45, Monitor 75 CP, each +0.25 per click, so a click reaches 2 CP; then the Server Rack, 100 CP, +1), then ×1.32 per level through Macro Pad → Summer Intern → Team of Interns → Crowdsourcing Platform → Click Farm → Robotic Clicker Arms, each stage adding more CP per click per level (`clickToolPower`). The card's name and flavour follow the stage (`upgradeName`/`upgradeFlavor`), and its line never names the next one (growing into it is a surprise; it goes to the log). Software multipliers: Compiler Optimizations and Kernel Fusion (+50% hardware each); NLP ×1.5 and Computer Vision ×2 Data crawler speed. Tested: the ladder's ratios, the doublings, the reveal rule, and that Server Cluster no longer touches clicks.
- **Achievements** are recognition only, with no production bonus (they used to add +2% each, which made a click 1.02). Versions (Insight, `globalMultiplier`) are the only global multiplier.
- **Hand actions pay whole numbers:** a click, a collection or a research run by hand adds only flat amounts (the click tool, Data Processor, the algorithms, skills' `click`/`collect`/`research`). Percentage bonuses (skills' `dp`/`rp`, Insight) go to what runs by itself: hardware, the Data crawler and Research Assistant (`autoDpPerCollect`, `autoRpPerResearch`) and training XP. A click never reads 2.3 DP or 3.60 CP (tested).
- **Supply chain:** the lab produces compute and data, training sprints spend them, and learned skills boost the lab and unlock its automation. The Training Cluster bar shows the lab's supply.
- **Tree pricing:** a node's first level always costs more than its parent's last level (tested), so finishing a node is never worse value than skipping ahead (Lucky Break 2 used to equal Serendipity 1). **No repeats down a path or across siblings:** a node never boosts the same stat as the node it grows from, and nodes growing from the same node never share a stat either (both tested), so each step and each choice feels new. **The shape stays mirror-symmetric:** the inner ring branches both ways off Power (Batch Normalization right, Smoother Loss Landscape left) and Recursion (Warm Restarts left, Data Augmentation right) while Momentum and Precision run straight, because one side node per arm, each bent the same way round, read as a swastika. Paths: Power runs GPU Cluster (strength) → Fast Charging → GPU Supercluster (strength) → Max Effort → Exascale (strength) → Fusion Reactor (breakthrough power) → Dyson Swarm (strength), with Liquid Cooling (drag), Quantum Accelerator (Max Effort power) and the luck nodes off to the side, and Max Effort a single level so it doesn't wall off the strength behind it; Momentum alternates drag and hills; Recursion's two columns alternate sprints and wait (Bridge Round, Strategic Partner, Hiring Spree, Round-the-Clock Ops); Initial Weights gives clean-prompt XP.
- **Data stays data:** only the Data Processor raises data per collection; NLP and Computer Vision make the Data crawler faster (×1.5, ×2) and grant no Intelligence (Intelligence comes from training and the algorithms; Self-Improve, a direct +5 Intelligence that skipped the Training Path to General AI, is gone).
- **Early pacing (nothing before it makes sense):** the click tool (15 computes) → your desk, one item at a time → the Graphics Card after the Server Rack → Collect Data at 5 CP/s (and the software terminal and lab log with the first data) → the server room once you've collected data 40 times by hand and built a stockpile (100 CP, 40 DP held; `module:path`), so data matters before a skill automates it → Server Cluster only after the first training run (`tierReady` and `stats.rolls`), so it doesn't arrive with the server room → Research 50 training sprints after the first skill: research is the vehicle for bigger projects, and it brings the investors, whose offers point the player toward shipping the next version (a `Research funded` callout says so).
- **Reveals:** top-bar chips appear only once they matter (`REVEALS` in `engine.js`: `seen:dp`, `seen:int`, `seen:cre`, `seen:awa`; the phase bar shows with Intelligence). Each is introduced once with a toast and a log line. XP lives in the Training Cluster bar, not the top bar. The Software station opens with `seen:dp`.
- **The lab splits by resource:** the hardware bench is all compute (the generator tiers, the click tool, Compiler Optimizations, Kernel Fusion), the software terminal is all data (Data Processor, Auto Data Collector, NLP, Computer Vision), the research wall holds research (Research Assistant and the algorithms), and investors pay in research. Tested.
- **Investor projects** (`engine.js`, save v3): investors fund research, so once the Training Cluster runs and Research is open, offers arrive every 2.5–5 min of game time (`PROJECTS`, at most 3), each an investor, an optional task with a deadline (`PROJECT_TASKS`: computes or collects by hand, finish runs, clean sprints, earn CP, research), and a reward in research points (`PROJECT_REWARDS`: +50% research for 5 min, research ×2 for 3 min, or a research grant, sized to your research rate). Older saves' compute, data, XP and sprint boosts still apply until they run out. Progress counts from when the offer arrived. Claim when done (`claimProject`), or ignore and it expires. Boosts multiply in `derive()` via `projectBoosts`. Seeded by `projects.seq`, so tests are deterministic. The lab shows them in the supply strip, with active boosts and timers; rows are rebuilt only when the offers change.
- **Offline progress** is applied on load and for long gaps between ticks, capped at `MAX_OFFLINE_SECONDS`, and respects `settings.offline`.
- Keep `engine.js` free of DOM/`window` so it stays testable.
- **Training Path** (how the AI learns):
  - The trail is a series of stretches. Stretch k runs from a checkpoint to **skill hill k** (fixed, grows each stretch). Cresting it learns `skillAt(k)`: attributes plus a permanent bonus summed in `derive()` via `skillBonuses()`.
  - Each **roll** starts at the checkpoint over **random rolling hills** (`rollingHills(k, seed)`, new seed per roll from `rollSeed`). The roll ends only when the ball rests with no pushes left (or rolls back past the start): **a skill hill never cuts a run short.** Distance earns **XP** (`finishRoll`), and the furthest roll is the stretch record (`path.best`).
  - **Flat start:** nothing is behind the start line (no wall, no previous hill), and a ball that rolls back past it (`ROLL_BACK`) ends the run (`end` with `rolledBack: true`, progress 0, paying for half the furthest distance reached; the card says "Rolled back to the start"). The drawing is flat there too, except in the post-skill overview.
  - Once the ball lacks the energy to clear either neighbouring hill it is "trapped" and gets heavy damping, so it settles in about a second instead of sloshing. Full momentum otherwise.
  - Pushes add a fixed amount of *energy* (pushing against a backward roll is wasted), and drag is partly quadratic. So saving pushes to rescue a stalling ball beats firing them early. Tests guard this; keep it true when tuning.
  - **Pushing is hold-to-charge.** A meter sweeps up and down while the button (or Space/Enter, or the canvas) is held, and release fires at that fraction of `pushPower`.
    - Every push costs CP and DP by `pushCost(s, charge)` (∝ charge², scaled per stretch), so passive income gates how hard you can push. The meter only reaches `affordableCharge()`.
    - Each push has a **bonus zone** (`bonusZone(seed, index, width, perfect, system)`, centred between 50% and 85%), and `zoneHit()` classifies a release as `'clean'`, `'perfect'`, `'system'` or none. **Players read these as prompts:** a *clean prompt* (the zone), a *super prompt* (the perfect spot, from Prompt Engineering) and a *system prompt* (a 1% sliver inside the super prompt, legacy System Prompt, worth `systemMult` 50 clean prompts). Code keeps `clean`/`perfect`.
    - A clean prompt banks a small flat amount of XP at once (`grantPushBonus`) and adds `cleanRollBonus` to the roll's distance XP; a super prompt counts as `perfectMult` clean ones (`cleanUnits`). This is the trade-off: steady XP from the zone, or full charge for distance.
    - **Prompts grow in order:** first the clean prompt (Hyperparameter Search: power; Benchmark Prizes: rewards; Prompt Templates: the zone 15% wider per level, the only widening, so it stays a skill; Prompt Tuning: `zoneBias`, zones sit higher on the meter, where sprints are stronger). The zone can land anywhere from 25% to 90% of the meter (`bonusZone(…, bias)`). Then super prompts: Prompt Engineering adds the spot, Few-Shot Examples its effects (+20% strength, +1 clean prompt's worth per level, `perfectUnits`), and only then Chain of Thought widens it (+40% per level, dear), so super prompts stay rare and rewarding. Upgrades make hitting them *pay*: a sprint's strength is `sprintStrength(s, fraction, kind, breakthrough, maxEffort)`, ×`cleanPower` in the zone (Hyperparameter Search +20%), ×`perfectPower` on the super prompt (+30% more) and ×`systemPower` on the system prompt. Benchmark and Leaderboard Prizes (flat XP), Curated and Hand-Labelled Data (run bonus). The meter shows the boosted strength while you're in the zone. Tested.
    - **No charging during the wait:** while the cooldown runs (or a breakthrough winds up) the meter greys out (`.charge.waiting`), the button counts down ("Next sprint in 1.2 s") and is disabled, and pressing does nothing: a sprint charges only when it can fire (`readyToFire`), so there's no queueing. Bullet Time is the exception (sprints bank whenever). The breakthrough's sprint lands at once (`roll.push`) while the wind-up holds the run still, and the cooldown keeps counting through the wind-up.
    - **Fast Charging** (`charge` stat → `sweepScale` < 1) makes the meter faster; the base sweep is `CHARGE_SWEEP_MS` 1250. The **Auto-Trainer** (legacy, 3 levels, `autoTrain`): level 1 starts runs and sprints at full budget once the ball settles; level 2 also sprints on a climb the ball won't make (moving forward uphill with less energy than the next crest needs, `wontClear`), when a sprint counts most; level 3 aims every sprint at the super prompt's centre (else the clean prompt's) and banks the prompt XP. It never sprints in the air.
    - **Power-ups** sit beside the nodes they grow out of: breakthroughs and Max Effort off Power, viral runs off Precision's XP nodes, crunches off Recursion's shorter waits, Flow State off Momentum's lower drag and hills. **Lean strong:** things should get wild early rather than feel like they've slowed down, so chances are generous (breakthroughs 4% per Lucky Break level and 5% per Black Swan, ×1.75 base; Max Effort 5%, The Muse 3%; viral 5%; crunches 4%; capped at 50%), and each super is 25% of its kind per level; **legacy nodes** (Insight, below) add chance, power and flat amounts, and hold Flow and every super kind. Rolled deterministically from the roll seed and push index (`luck()`, the `*Hit` helpers and `superHit(s, kind, …)`), so tests and the sim are repeatable. Each has its own look (`game.js` "Luck effects (power-ups)", `drawLuckUnder`/`drawLuckOver`, a big banner via `luckBanner`, styles.css "Luck"):
      - *Breakthrough* (Lucky Break, Serendipity, Black Swan; legacy Scaling Laws: `critChance`, `critMult` from ×1.5): the sprint hits harder. On screen the ball **winds up** first (`WINDUP_SECONDS`, the run holds still): it glows, shakes and draws sparks in, then takes off with a shockwave, a golden streak and a jolt. *Paradigm Shift* (legacy, `superCrit`): a share of breakthroughs also smash through the rolling hills ahead (`roll.smash(reach)` flattens them at once in the physics; skill hills stand). On screen it's a break-through: a white flash and a hard shake, a blast of light running along the ground, and each hill drawn as slabs cut from its old outline (`shatter`, `fx.shards`) that hang with glowing seams in a wave out from the ball, then blow apart, spinning and falling, with dust.
      - *Max Effort* (Max Effort, The Muse; legacy Second Wind: `maxEffortChance`, `maxEffortMult`): your next sprint goes all out the moment you press: full strength (what you can afford), a super prompt, ×`maxEffortMult`. Manual sprints only, and only rolled when a sprint is left to spend it on; through the cooldown the button counts down ("MAX EFFORT in 1.2 s"). A gold meter and button. (It replaced the old Flow State, which made the next sprint perfect: everyone just aimed for the zone anyway.)
      - *Viral run* (Viral Paper, Keynote Demo; legacy Press Office: `windfallChance`, `windfallMult` from ×2): the run's distance XP is multiplied. Reactions pour off the ball, and the result card gets an animated rainbow edge and a "VIRAL ×N" stamp.
      - *Crunch Time* (Crunch Time, Death March; legacy Hackathon: `crunchChance`, `crunchSeconds` 3 s +1 per level): a paid sprint can set off a crunch: for a few seconds every sprint is free (`roll.push(strength, true)` with a 0.35 s wait), and `holdOpen` keeps a resting ball's run going. A fiery aura, a countdown ring, a burning button. *Bullet Time* (legacy, `superCrunch`, `freezeTime`): time freezes instead (the run holds still, `path.fx.freeze`); every tap banks a full-strength sprint ×1.5 (`BANK_MULT`, `path.fx.bank`) however short, so mashing is the play, and it all lands at once when time restarts (`roll.boost`). The world drains to grey (a `grayscale` canvas filter on the terrain; the ball keeps its colour) under a cold tint, dust hangs in the air, a clock face round the ball ticks down, each banked sprint waits as a chevron ahead of it, and the release comes with a white flash, shockwaves, streaks rushing past and "×N RELEASED".
      - *Flow State* (legacy only, `flowChance` 3% per level, `flowSeconds` 2 s + levels, Deep Focus `flowSpeed`). The ball lifts off the line and coasts for a few seconds at no less than a share of a full sprint's speed, ignoring hills and drag (`roll.coast(seconds, speed)`). It flies high: up to mid-sky, or clear of the tallest hill in view, with a slow bob, a ribbon trailing behind and a dotted tether to its shadow on the line; calm lights drift up through the view, and the whole trail swells to a slow beat (`FLOW_BPM`; labels and HUD are drawn outside the pulse). *Lucid Dream* (legacy, `superFlow`): you lose track of time. The timeline condenses: for the flow's seconds each physics step carries the ball `LUCID_WARP` (4) times as far (`coast(…, warp)`), so it covers far more ground than it could (and can crest skill hills mid-dream), and the view squeezes `LUCID_CONDENSE` (3) times wider while heights keep their scale (`cameraTarget`'s `condense`, eased with the camera and divided back out of the vertical scale), as if a lot of time has passed. Violet streaks rush past, the sky cycles dusk to night, with violet ripples on the beat. (`coast` can still shrink and narrow hills, `shrink`/`narrow`; nothing uses it now.)
      - Reshaped hills ease to their new height and width inside the physics (`RESHAPE_RATE`), so the drawing follows it; smashed ones go flat at once (the slabs carry the drawing). Big hits shake the whole view (`fx.shake`) and flash it (`fx.flash`).
    - XP follows the ball: the live pill shows `rollXp` at the ball's *current* position, and the payout uses where it stops (rolling back loses XP). The result card sits top-right, clear of the checkpoint; launching fades it.
  - Slope friction (`SLOPE_DRAG`): steeper slopes sap more speed than gentle ones.
  - **Friction stays a skill.** Upgrades only take the edge off: each drag step is −5% (`friction`), and "less steep hills" (`slope` stat → `hillScale`, ×0.94 per step) really lowers the *rolling* hills, never the skill hills (`rollingHills(k, seed, hillScale)`). Skills add little glide. Don't make hills trivial.
  - **Difficulty grows every stretch:** `skillHeight` ×1.5 per stretch, and `stretchLength` = 10·1.4^k + 3k (10, 17, 26, 36, 50, 69, 93, 124, 166 by stretch 8; `training-path.js`): gentle early, so the second skill isn't a wall, then much longer each stretch, so the distance itself becomes the challenge and strength (and later launches and bounces) matters more than the hill count. Legs 1–9 are many small rolling hills (their count grows with the length). **From leg 10 (`LATE_LEG`) the game turns into a launcher** (think Learn to Fly, Toss the Turtle, Burrito Bison): each leg is 5–7 giant swells (`swells`, a few more every three legs), tens of metres wide and 35–65% of the skill hill's height, far bigger than the view, and the skill hills widen 8× to match (`skillHalfWidth`; `legMetres` in the engine mirrors it, tested). Chosen by simulating several curves for the steadiest growth in the gaps between skills; doubling every stretch from the second made the second skill a 35-minute wall. Later stretches pay more (they're longer, and `metreScale`). Skills answer with growing bonuses (push %, extra pushes, a little glide; `SKILLS` and frontier skills), and the tree's outer ring (Quantum Accelerator, Exascale Cluster, Superconductors, Neural Compression, IPO) is priced for the late hills.
  - **Cleared legs replicate their best run:** each learned leg earns passive XP per second equal to `PATH.clearedRate` (1/1200) of the best run that started on it (`path.legBest[k]`, recorded by `recordRun` at every run's end, never less than a plain cresting run, `legBestXp`/`legXpRate`; save v6), applied in `tick()` and shown on the XP chip and its Scheduled tasks row. So replaying a leg with better upgrades (clean prompts, chains, strength) raises its passive XP; a replay that beats the best says so on its result card.
  - **Replays (legs):** every cleared stretch is a leg you can run again. A run can start on any cleared leg (`createRoll(k, seed, { last })` builds the terrain from leg k through the frontier, each leg with its own rolling hills from `legSeed`), and keeps rolling through every later leg. Crossing a cleared leg's skill hill emits `clear` and pays flat XP at once (`clearLeg()`: `PATH.replayXp` (100%) of that leg's full XP, more for later legs). The roll ends like any other: where it stops (`end` events carry the `leg` and the `progress` along it). On a replay, distance and clean or perfect sprints pay at the **frontier's** rate times the replay share (a metre is a metre, and a perfect on leg 1 is worth one on the frontier; sized by the leg they were worth a fraction). Only the frontier sets records and teaches skills. Pushes cost what they cost on the leg the ball is on (`pushCost(s, charge, leg)`), so later upgrades make early legs quick and cheap. **The chain:** each cleared hill crossed in a run adds `PATH.chainBonus` (+0.5×) to everything the run earns after it (`chainMult(n)`: later clears and the distance at the end), shown on the live XP pill ("chain ×2"), in the cleared flash and on the result card. Tuned with the balance bot against its own states at 3, 6 and 9 skills (`chain2.js`-style: frontier runs against runs from leg 1, **counting clean and perfect sprints**, for a half-clean bot and an all-clean player): a replay pays 1.2–1.6× a frontier run per run and 0.6–1.1× per minute (it takes about twice as long). Runs from leg 1 stall about halfway through the cleared legs. Smaller settings (25–75% share, +0.25–1×) left replays at 70–100 XP against 200+ on the frontier. Pick the leg by clicking a cleared lane on the rack (it shows "▶ Replay" on hover; the rest of the bay opens the frontier) or with **Start at** on the dev screen (Leg 1 first, the frontier last); a tag on the trail shows a replay, and its × goes back to the frontier (`path.startLeg`, screen state only).
  - **Cleared stretches lap themselves:** each counts automated laps (`state.path.auto[k]`, one per `clearedPeriod(k)` = 40 + 5k s, counted in `tick()`, save v4), shown on the rack's cleared lanes and its Scheduled tasks row with its XP/s. They add no compute (the old +3% per stretch and +0.2% per lap trickle, like Shell Scripts' 2% of CP/s on clicks, made numbers fractional and was removed).
  - **Drama** (`game.js`):
    - A *nail-biter* (`nailBiter()`) is rare: the ball within 5% of the top of a big hill (the skill hill, or a rolling one at least 60% of its height) with about as much energy as it needs, at most once every 8 s (`path.dramaQuiet`). The follow camera zooms out at once for tall hills but only zooms back in once it could be 30% tighter (`path.camView`), so it doesn't keep breathing. It brings slow motion (`path.timeScale`), a camera push-in raised to the ball (`cameraTarget` with `cam.bottom`), a vignette and "Will it learn <skill>?" (or "Come on…" on a rolling hill).
    - **Runs go on past the skill hill** (`onward`): cresting the frontier's hill emits `crest`, and `crestFrontier` learns the skill at once (`E.crestSkill`: the leg's full distance XP ×2, times the chain so far), fires `celebrateSummit()` (a SUMMIT! banner, confetti across the whole trail, slow motion, the push-in held on that hill), adds the hill to the chain and calls `roll.extend()` to lay the next leg ahead (the terrain is extendable: `ground.goal`/`last` move on). The run keeps going as far as its momentum, sprints and luck carry it, learning more skills on the way if it's strong or lucky enough. The result card lists every skill learned on the way ("2 skills learned"), their cresting XP and how far into the next leg it got. (`rollOut`, the old stop-at-the-crest behaviour, remains for the debug summit test.)
    - Slow motion only applies on screen; background runs keep real time.

A hard landing (the settle can't absorb it, e.g. a sprint just before touchdown) reflects off the ground's normal: `BOUNCE` 0.42 of the impact comes back and `SKID` 0.82 of the speed along the ground is kept, so it bounces on until the bounce is under `BOUNCE_MIN`, then rolls on (a `land` event with the flight's length and height). A bounce that would throw it backwards (slamming into the face of the next swell) sticks and carries its speed up the slope instead: launchers keep you going forward. A sprint in the air boosts the ball along its flight (`addEnergy`, plus a little lift), like firing a booster mid-air. Rolling there keeps its momentum (`LATE_DRAG`: a quarter of the quadratic and slope drag), and the "trapped" damping only settles the ball near a valley's floor, not mid-slope. ## Screen layout

Everything grows as it unlocks, and locked things never say what they are: a sealed placeholder (`???`) hints that more is coming where that means something (rooms, bays, tree locks). Keep it that way when adding content.

**Layout stability:** players should find things where they left them. Every panel has a reserved home: new things fill reserved space or grow into empty floor, never insert above or before what's there, and nothing resizes because of a click. Lists that grow scroll inside their panel; items never vanish from under the pointer (investor offers keep their slot; a finished one-time card only leaves after you bought it, with an animation); text that changes length is clipped to one line (`room-goal`, action automation lines, top-bar numbers keep a minimum width). One-off reveals may extend the layout outward. Check new UI by recording panel rects before and after a purchase (`lab2.js`-style Playwright check).

**Reveals animate:** nothing pops in. Anything shown through `setHidden` that matches `REVEAL` (panels, stations, supply cells, chips, workbench jobs, tasks, cards, tree nodes, facility tiles) boots up (`revealIn`, `.reveal-in`, 1.5 s: a scan wipe with a bright edge, a flicker, a fading glow), never on load, in camera copies or under reduced motion. In the lab, what's already there **makes room first** (`makeRoom`, 750 ms: a snapshot before the change, then panels, stations, supply cells, jobs and tasks slide and resize from where they were, without scaling their text) and the new section waits until then to boot in. Show new UI with `setHidden`, not `.hidden =`, so it gets this.

**Information grows with the game:** show only what matters at this stage (top-bar chips, supply cells, stations, automation lines appear when they mean something), and add detail as systems open rather than all at once.

Every kind starts as a small 1×1 square. **Merges need direct contact:** the right number of the same kind and size touching in one straight line (horizontal or vertical), exactly the merged piece's shape, become a medium bar, and mediums touching in a line become a large piece, wider before taller (`buildRacks` replays the buy log; a piece at the end of a row and one starting the next row don't touch, so they don't merge).
