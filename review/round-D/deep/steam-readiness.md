# Steam / desktop-wrapper readiness (build 92a207b)

- **Network:** the only runtime network dependency is Google Fonts (`index.html` lines 10-12: Chakra Petch, Atkinson Hyperlegible, JetBrains Mono). Offline, the page falls back to system fonts and the layout (tuned to those metrics) shifts. Bundle the three families (all SIL OFL) as local `@font-face` files. Nothing else fetches (no fetch/XHR/WebSocket/beacon in any script).
- **Storage:** every read/write goes through `storageGet`/`storageSet` on `localStorage` (save ~1-5 KB JSON, backup `agiGame.bak`, corrupt copy, plus ~12 per-device keys). Electron/NW.js persist `localStorage` per profile, so it works as is; Steam Cloud needs the save as a file: add a small adapter (one key -> one file) behind `storageGet`/`storageSet`. Saves are versioned and migrate from v1, so cloud conflicts reduce to "newest `lastSaved` wins" (the import dialog already shows both summaries).
- **Tab lock:** `claimTab` uses `BroadcastChannel`; in a single-window wrapper it is harmless (and gives up quietly where refused).
- **No offline progress / hidden tab:** `tick()` returns while `document.hidden`. Electron windows that are minimised report hidden (fine, by design); a wrapper that keeps rendering in the background (`backgroundThrottling: false`) would still not earn, because the gate is `document.hidden`, not timers.
- **Window sizing:** content uses the full width with CSS `zoom` tiers at 2200/3000/3600 px and phone tiers below 640/960 px; set a minimum window of about 1024 x 640 (the desktop layout's floor; smaller falls into the tablet/phone tiers, which work but look like a phone).
- **Input:** mouse, touch, keyboard (Space/Enter sprint, U, R, Esc, backtick for debug). Hold-to-repeat and hold-to-charge use pointer events. Gamepad: none (Steam Deck would need Steam Input's mouse/keyboard mapping or a small Gamepad API layer for sprint/thrust and navigation). Remove or gate the debug panel (backtick, `#debug`) in a release build.
- **Audio:** WebAudio synthesised, no files; it unlocks on the first gesture, which Electron allows without one (`autoplayPolicy: 'no-user-gesture-required'`).
- **Performance headroom:** idle CPU is dominated by rendering, not JS (profile of the act-two run view at 1x: 49% "(program)" (style/paint/raster), JS functions each <=1.1%); a GPU-backed wrapper should hold 60 fps where headless software rendering held 30 fps in the lab.
- **Artifact-only code:** `window.claude?.hot` hand-over and the "Keep the screen on" wake lock are no-ops in a wrapper.
